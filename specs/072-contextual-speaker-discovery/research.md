# Research: contextual speaker discovery

Date: 2026-11-02. Three read-only planning investigations covered catalog persistence, provider/runtime integration and resolution provenance. No unresolved research questions remain.

## Decisions

1. Store one typed current discovery aggregate per recording, with a source-specific frozen epoch, an accepted work reference and proof-bearing receipts. Generic work carries execution state and reference-only results. Alternatives were rich work results (forbidden content and weak current authority) and standalone artifact history (unnecessary lifecycle expansion). Invalidate the aggregate transactionally when its source authority changes; historical receipt replay must never resurrect content.
2. Advance the catalog from schema 11 to 12, freezing exact v11 DDL/digest before changing reflective records. Create the table in every historical migration path, include it in portable export/restore, and validate its latest proof, epoch and recording references. Both SQLite and PostgreSQL use the same domain and acceptance suite.
3. Add a dependency-free internal/speakerdiscovery package for typed evidence, strict provider parsing and deterministic resolution. Catalog can depend on it without importing the existing speakers package, which already imports catalog. App owns assistance configuration and provider execution.
4. Use assistance.Normalize and HTTPAdapter.Generate for elected insonic-http/Ollama routes and protected credentials. Use one parent TimeoutMS deadline across all chunks, cancellation and acceptance. Reject the complete response for duplicate JSON keys, unknown fields, invalid/foreign IDs, invented authoritative timing, missing quotations or exceeded limits. Do not reuse extraction code that drops invalid assertions or continues after provider failures. No repair call is required; failure is explicit and retryable.
5. Provider context contains only selected current cue text/IDs, attributed voices and relevant canonical names/aliases/roster hints. Acoustic predictions stay out of this prompt. Exact quotation validation establishes occurrence, not semantic model accuracy. Self-identification requires a single attributable voice and direct utterance; quoted or mentioned people cannot assign the current voice. Preserve role/relationship context, abstention and competing candidates.
6. Defaults/caps: selected cues 100/500, provider calls 4/20, observations 128/512; at most 16 references per observation, 512 UTF-8 bytes per name/role/alias selector, 1000 voices or roster members, and 1 MiB accepted aggregate. Each call respects assistance context limits (at most 25 cues and 32768 context bytes), prompt limits and response limits. Coverage reports total, selected and omitted cues; truncation never masquerades as a whole-recording unknown. Reject overlarge mandatory identity context with input_limit. Existing transport and credential bounds remain unchanged.
7. Resolution uses exact normalized names and aliases, preserving all matching person IDs, language and scope. It never merges people with equal names. Policy allows minimum contextual roots (default 1, range 1-16), minimum acoustic score (default 0.8, range 0-1) and minimum margin (default 0.1, range 0-1). Roots derive from original source digest/track/channel/time overlap; repeated rows, recordings or provider calls do not create independence. Unknown overlap does not provide a second root.
8. Reuse only authenticated accepted recordings.match work. Never invoke ExecuteMatch, which commits automatic mappings. An optional matching_work_id selects exactly one work; otherwise use current automatic mapping provenance, then the latest accepted match receipt for this recording. Verify work journal digest, accepted matching receipt, current post-match mapping digest and matching snapshot. Normalize only the fresh pre/post mapping digest difference introduced by matching itself. Stale/unavailable proof remains visible but is not support.
9. Independently corroborating profiles require current output metadata, current dataset/manual enrollment references and no overlapping or unverifiable enrollment/evaluation roots. Profile reassociation remains valid. Old artifact availability is not current training authority. Existing ambiguous acoustic results omit candidate scores/identities: report ambiguity and eligible profiles without inventing rankings.
10. Outcome precedence preserves owner authority and uncertainty: incompatible independently supported identities are conflicting; multiple plausible identities or close authenticated acoustic alternatives are ambiguous; a current independent accepted acoustic match can be matched; qualifying contextual evidence can be supported-contextual; otherwise unknown. An unregistered self-introduction retains a supported name with speaker_id null and identity_status unregistered. Mapping/profile/source state never changes.
11. Provide speakers discover, hypotheses and resolve through the shared runtime, human/JSON CLI and desktop Operate bridge. Discovery is durable work; resolution is deterministic over a frozen current aggregate. Full saved-pipeline orchestration and applying/enrolling results remain #230-#232. No new issue, software version change or release publication is part of this slice.

## Evidence boundaries

Protocol fixtures establish parsing, citations, deterministic rules, current authority and recovery. They do not establish accuracy for an unelected real model. Hosted CI supplies native and backend evidence; no active-desktop GUI test is authorized. Final PR handoff requires exact-head green applicable CI, addressed findings and at most two review rounds.
