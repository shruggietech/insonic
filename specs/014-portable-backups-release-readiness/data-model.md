# Data model

Backup manifest uses the synchronized contract version (baseline 0.0.0) and binds workspace UUID, captured-source and portable catalog revision/digests, mode, snapshot SHA-256, exact publication identities/profile revisions/object versions/digests/lengths, completion proof and graph rebuild disposition. Self-contained objects use digest-addressed private files. Reference-only manifests declare source profile dependency and durable backup-owned references. States: preparing -> verified -> complete -> released; failed preparation never advertises complete.

Portable restore validates source receipts and all relationships, admits destination profile/relocation receipts with stable publication identities, resets graph materialization checkpoints and activates only an empty destination transaction. Durable pending/completed activation receipts bind the exact physical destination profiles. Transfer ownership uses owner/generation fencing; stale authority cannot write. Private multipart progress binds upload IDs and parts to that destination. Credentials are destination configuration and never bundle values; an optional local credential namespace remains independent of imported catalog identity.

Release manifest uses the synchronized contract version and binds software/docs/schema version, exact 40-character source commit, six platform/variant assets, source inventory, capabilities, signing disposition and SHA-256. States: candidate -> verified draft -> published -> documentation promoted. Failures before publication retain draft; no docs promotion. Existing historical issue state/body/project values remain user-owned; new issues use exactly one canonical type/priority/effort and meaningful areas.
