# Native lifecycle and evidence contract

Startup follows owned host/thread creation, environment/controller initialization, accepted navigation, native resource callback, asynchronous application handler, framework HTML rewriting, native response publication, deferral completion, browser navigation and frontend readiness. Each is a separate boundary.

Shutdown follows actual native action/callback, normal host-window destruction, controller Close, retained-interface release, COM balancing, host exit and natural owned-browser process release. Independently owned runtime jobs survive.

Qualification retains its existing 12-second child watchdog, two-second native UI joins, real native menu/close/Alt+F4 paths and shared 18-second root-plus-descendant deadline. A passed action JSON or root exit zero does not prove natural descendant release. A timeout remains failed after cleanup.

Existing response-counter observations operate only under disposable qualification, preserve argument values/call counts/error propagation, and do not change focus, timing deadlines or fallback behavior. After E006, a separately elected browser observer may add documented read-only CDP setup and one actual environment-version query. Its enable acknowledgements precede diagnostic navigation, so the scheduling difference is explicit; it is excluded from ordinary startup and final product qualification. It never changes the original watchdog or treats setup failure as an incident cause. Native wrapper regressions call actual vtables. Any observed runtime selection records both availability and actual created-environment version. Environment-variable overrides do not count as a control when the loader clears them.

Every source update retains exact upstream version/hash authority, explicit modified/added file allowlists, notices and corresponding-source package identity. Final S040 qualification requires passing checks on its own final head; S039's historical exception is not inherited.
