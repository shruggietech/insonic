# Publication evidence model

Release source identifies the full commit, tree, version and accepted source checks. It is immutable throughout qualification and publication.

Candidate identifies its producing run/attempt, ten original filenames, byte lengths, SHA-256 digests, package receipts and both release-status documentation archives. Every file must match its retained digest; absent or conflicting identity fails acceptance.

Real campaign evidence binds the original Windows CLI digest and source to pinned model/fixture identities, CPU and NVIDIA outcomes, readiness, timing and cleanup. Failures and abstentions remain part of the record.

Publication identifies the immutable tag, official release URL and independently downloaded inventory. Deployment identifies staged tree, parent, pushed commit, terminal build and live resource comparison. Neither metadata alone nor unrelated completed builds establish downloaded bytes or deployed content.

Delivery evidence references these records, requirements/tasks, local/hosted checks, review rounds and unresolved limits. It excludes credentials, private corpus paths and executable bot mentions.

State order: source verified -> candidate retained and qualified -> devices qualified -> tag and release published -> documentation deployed -> independent verification -> reviewed evidence PR -> owner merge. Uncertainty retains exact identities and diagnostic observations; it does not advance state.
