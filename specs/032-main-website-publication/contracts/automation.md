# Maintainer automation contract

Manual website dispatch selects exact revision and runs workflow definition from main. Read-only build qualifies current main. Publication checks out trusted main tooling, independently checks same-run data and release/source/destination, then advances only gh-pages. Original release promotion shares destination concurrency. Website commands contain no tag/release/asset writes.

CLI phases: prepare, publish, verify, verify-deployed (read-only exact destination data). Aggregate owned-process deadlines; nonzero failure with phase receipts. Browser fetches only bounded approved production resources and closes its own profile/process.

CI foundation/scope independent. Unknown or mixed product/workflow changes elect full checks. Media starts after scope; runtime/package/adapters also require foundation. docs-build uploads bound archives; stable docs performs renderer/browser qualification. Native opts in with false-default boolean and fails on drift; release independently builds. Aggregation requires foundation/docs/both package success.

Owner retains final merge and subsequent production publication. At most two actual external code/security review rounds.
