# S023 dependency and evidence model

A DependencyElection identifies source PR, captured immutable PR commit, requested version, immutable action commit or locked module integrity, affected owned declaration and implemented commit. All seven elections are retained in research.md. A bot rebase cannot silently alter the captured input. Runtime closure adds text 0.43 and sync 0.24; native/toolchain identities are unchanged.

QualificationEvidence identifies source revision, workflow run/attempt, OS, variant, result and retained source/package/documentation receipts. Candidate admission requires both supported platforms and both package variants from one source/attempt. Cache reuse is evidence-bound, not proof merely from key lookup.

ArtifactTransport retains archived uploads with stable configured names, extracted downloads and strict digest failure. Existing byte-level transfer/candidate verifiers continue validating contents, source, recipe, compiler, attempt, inventories and sources. This is an internal build-interface contract; no application schema or user configuration changes.

Consolidation progresses specified -> implemented -> qualified -> owner-reviewed/merged. The official PR links its tracking issue and seven originals. Original bot PRs stay open until owner merge, then become eligible for superseded closure. No independent original merge or automatic product release occurs.
