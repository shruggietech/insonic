# Research: v1 release qualification

2026-10-10: Spec Kit plan Phase 0 dispatched independent read-only research for version/history, acoustic journey and package/candidate authority. Existing product contracts remain authoritative.

## Decisions

1. **D01, candidate status**: Prepare 1.0.0 without describing it as published. Existing preparation incorrectly promotes documentation status; correct preparation semantics and test them before running it. A public release is a separate operation.
2. **D02, historical authority**: Preserve baseline schemas/docs and historical compatibility fixtures. Update current runtime/schema bindings explicitly rather than applying indiscriminate version rewriting. The existing preparer is the starting point, not permission to repeat poor logic.
3. **D03, connected journey**: Extend qualification through actual shared runtime/CLI contracts, then compare restored current authority with the completed source workspace while source storage is unavailable. Separate deterministic CI from elected real-engine runs.
4. **D04, real acoustic scope**: Existing Windows CPU faster-whisper/Community-1 environments and exact model bytes are available. Use offline selected tools, hidden supervised execution and explicit resource limits. Built-in pyannote-profile produces actual embedding enrollment, not base-weight retraining; generic training adapters remain separately contract-qualified.
5. **D05, asset authority**: Reuse successful same-run CI package lanes, retain all six actual archives, package matching docs and collect a candidate in an unprivileged dependent job. Every identity uses the actual clean PR merge revision, not an unrelated branch-head label.
6. **D06, configuration readiness**: Read-only GitHub inspection found no repository signing/deployment variables or repository secret names and no documentation-deployment environment. Report unconfigured status. Do not invent an identity, host or credentials.
7. **D07, dependencies**: Integrate PR #41's exact go-winio 0.6.3 and x/sys 0.49.0 changes, followed by native/credential qualification. Preserve other pins.
8. **D08, major-version documentation**: Rescan all documentation technical terms and extend the glossary with precise primary references and local usage. Preserve public contracts and the advanced CLI capability matrix, with one concise unpublished-candidate status statement.
9. **D09, delivery boundary**: Issue #42 and milestone v1.0.0 release candidate track S015. Owner authorized push/official PR and two review rounds; no tag, product release, deployment or merge is performed.
10. **D10, timing**: Measure full cached CI including candidate collection. Retain all integrity checks. The prior recipe's cold-bootstrap exception does not excuse cached overrun or authorize an unmeasured future cold path.
11. **D11, measured boundary correction**: The actual pinned Whisper decoder emitted a final 8.08-second endpoint for eight seconds of decoded speech. Rejecting that bounded prediction prevented connected processing. Elect an explicit end/media intersection of at most 250 milliseconds, diagnose each exact change and preserve strict generic adapters, negative/reversed intervals and larger excursions. This follows the existing bounded, diagnosed local-model boundary pattern without extending audio or inventing source timing.

## Alternatives considered

- Re-running all packaging in a second release dispatch duplicates qualified work and increases turnaround; same-run artifact collection provides complete real assets without publication permissions.
- Describing preparation as release would obscure the user's final merge/publication boundary; candidate status remains explicit.
- Running acoustic models in CI violates the existing elected-maintainer contract and adds large uncontrolled downloads; use existing local environments separately.
- Calling profile enrollment base-weight training would overstate behavior; record actual adapter semantics and measured results.
- Adding dedicated backup GUI controls expands an already approved advanced CLI scope and does not resolve the qualification boundary.
