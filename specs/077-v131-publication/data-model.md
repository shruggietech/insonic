# Publication evidence model

- AcceptedSource: revision exactly 1443198e0dec4738c129bb6dfe48baba9830d6e3, clean status, version 1.3.1 and successful required source checks.
- Candidate: run/attempt/revision, original artifact size/digest, exactly ten file identities, four package variants, original installer/docs/source/signing/qualification receipts. State: prepared -> independently accepted -> immutable publication input.
- ModelCampaign: candidate archive/inventory/executable identities, exact model manifest/blobs and configuration/corpus identities, all seven scored cases, phase timestamps and owned cleanup. State: prepared -> qualified or retained failure.
- Publication: immutable exact tag, verified draft asset identities, published release ID/time and unchanged complete files. A partial draft is not public success.
- Deployment: original archive identity, previous/staged/pushed/deployed commits, single-parent/non-force update and exact completed Pages build. Ambiguous write -> retained attempt -> read-only exact reconciliation.
- Verification: fresh complete downloaded file comparison, expected original release content and exact deployed tree, path/resource inventory, six product targets, eight screenshots and cleanup. API metadata, saved bytes and rendering are distinct observations.

All identity mismatches abort the affected operation. Retain every failed observation. No accepted product data or catalog schema changes.
