## User Scenarios & Testing

### User Story 1 - Download the qualified patch (Priority: P1)

Users receive the answer/startup fixes in official version-matched Windows and Linux packages, built from reviewed merged source with complete provenance.

**Why this priority**: Merged fixes remain unavailable to users until original qualified packages are published.

**Independent Test**: Verify all published files against a retained accepted candidate and repeat the affected frozen model cases using its original installed CLI.

**Acceptance Scenarios**:

1. **Given** successful required merged-main CI, **When** the release candidate is built, **Then** all product and documentation files identify the same selected clean source and v1.3.1.
2. **Given** the accepted candidate, **When** publication completes, **Then** the official immutable tag and every public file match the accepted source and bytes, without rebuilding after acceptance.
3. **Given** its original installed Windows CLI and exact elected model, **When** the seven frozen answer cases run, **Then** all outcomes and applicable scores are retained, including supported Monday evidence and explicit uncertainty.

### User Story 2 - Read matching deployed documentation (Priority: P2)

Readers see released v1.3.1 documentation, schemas and official download links while historical documentation remains available.

**Why this priority**: Public guidance and downloads must describe the published product.

**Independent Test**: Compare deployed bytes with the original release documentation and exact Pages tree; inspect sampled desktop/mobile light/dark rendering.

**Acceptance Scenarios**:

1. **Given** verified published assets, **When** documentation is promoted, **Then** the selected exact Pages commit completes and released navigation/schema/download targets agree.
2. **Given** deployed content, **When** independent verification runs, **Then** the complete expected content, resources and download targets match retained authority and all eight sampled landing cases pass.
3. **Given** interrupted upload, uncertain promotion or concurrent Pages changes, **When** recovery is needed, **Then** original evidence remains retained and exact-identity reconciliation precedes further writes.

### Edge Cases

- Main CI fails, source moves, an incompatible tag/release already exists, or a candidate lacks complete files, notices, signing disposition or original qualification proof.
- Candidate-status documentation substituted for release-target documentation; stale navigation, missing historical routes, mismatched schemas or public binaries.
- Actual-model failures or zero-applicable metrics; missing package/model identity or unobserved process cleanup.
- Partial draft upload, download corruption, redirects, network limits, ambiguous Pages update and concurrent writers.
