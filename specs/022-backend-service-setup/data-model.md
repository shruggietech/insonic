# S022 data model

Backend plan: current schema_version, kind backend-plan, display_name and three role inputs (adapter_id, configuration, optional expected_backend_version). Workspace/profile IDs and revision 1 are generated by plan construction. Expected current configuration identity/revision is required before any replacement; populated target switching stays explicit migration.

Readiness report: schema version, checked_at, role, adapter_id, dimensions (syntax, reachability, transport, authentication, compatibility), structured field errors, correction codes and untested capabilities. No secret values or raw provider error bodies.

Candidate: endpoint, source/time, binary installation evidence, observed version, model name/digest/size/capabilities/remote metadata, endpoint scope and actual inference route. Limits: 16 candidates, 128 models, 1 MiB metadata, aggregate 30 seconds. Observation does not mutate configuration; stale observations are reprobed before selected inference.

Assistance configuration extends adapter enum with ollama, contract version 1. Native route local elects local inference even through a connected endpoint; hosted explicitly permits the inspected hosted model. Existing insonic-http semantics remain. Synthetic test state identifies exact selected endpoint/model and current configuration revision.

Credential bootstrap: protected input holds newly entered username/password for PostgreSQL/ArcadeDB, access_key/secret_key/optional session_token for S3, optional bearer token for Ollama, and optional vault passphrase/session map. Nonsecret references only remain in plan/config. Native/vault/session choice is explicit.

Lifecycle: plan construction assigns stable workspace/profile identities; a submitted generated plan is the retry identity. Repeating an identical committed plan reconciles success; differing content/revision conflicts. Candidate installed means observed executable/package evidence; running/reachable means valid bounded version response; compatible means advertised completion capability; configured means exact persisted election; tested means exact synthetic receipt. Before inference the selected model is reprobed.
