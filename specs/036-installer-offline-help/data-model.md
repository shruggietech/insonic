# S036 state model

No catalog migration. Installer operation is frozen as install/upgrade/change/repair/remove before execution. Engine progress is observed, never synthesized. Terminal result is success/cancel/failure. Only fresh interactive success exposes independent launch/documentation elections. Help identity binds a regular installed entry and matching bounded offline manifest; dispatch uses the selected OS association and existing same-user launch boundary.

## Upgrade recovery entities (owner-approved 2026-10-17)

RecoverySource identifies the original full local MSI by product/family/version, package identity, length and digest. It records a canonical application-owned local location and validation outcome. It is distinct from Windows Installer internal cache data. No source content is trusted solely because a filename or adjacent mutable JSON marker matches. Retention is not implemented until the synchronous recovery consumer is proved.

RecoverySnapshot records the previous installed product identity, absolute program directory, actual Core/Desktop/CLI feature states, elected shortcut integrations, owned payload inventory and validated RecoverySource. Capture occurs before old product removal. Existing installations may establish the source from a validated original local installer. Unavailable or corrupt source is a pre-removal failure, not permission to attempt destructive work.

RecoveryOutcome records the original native result, recovery operations/results, final product and feature registration, owned-byte verification, retained recovery location and cleanup result. Complete requires installed state5 and exact prior owned bytes/choices. Incomplete never becomes success because files exist. Retained recovery records remain scoped to the current user and application-owned data.
