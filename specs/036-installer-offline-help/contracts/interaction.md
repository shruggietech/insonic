# S036 interaction contracts

- Progress: modeless engine-driven phase/bar until a real terminal result; cancellation requests rollback where cancellable.
- Completion: operation-specific success; one Finish/Close with matching Esc behavior. Cancellation and failure cannot offer launch.
- Help: native desktop action is available before workspace selection; one compact control; actual installed HTML/version; locally generated actionable failures. No private-origin external URL.
- Launcher: explicit documentation mode shares installed-help validation and OS opening with desktop. Windows preserves non-elevated invoking user; no forced-browser fallback.
- MSI: client launch remains checked on fresh full-UI success; Open documentation is independent and unchecked. Neither action executes for other modes/outcomes. Documentation failure cannot fail the committed install.
- Verification: real transactions/activation receipts are distinct from portable model and restricted dialog rendering checks.

## Upgrade recovery completion

The recommended setup EXE coordinates the exact MSI in full UI and unattended mode and retains the original cancellation/failure code. Before the call returns, recover the prior registered installation when destructive work has occurred, using supported public Installer operations and the validated original full package. Complete recovery requires registration, choices and old bytes; UI and logs distinguish incomplete recovery. Missing/corrupt recovery data stops the upgrade before old removal and identifies the local-source correction. Fresh-install post-actions remain suppressed on every failure/cancellation. Successful upgrade/removal clean obsolete application-owned recovery material. The retained raw MSI exposes native engine results and has explicit recovery limits; it does not claim the coordinator guarantee. No elevation, external routing or Windows Installer internal registry/cache edits are introduced.
