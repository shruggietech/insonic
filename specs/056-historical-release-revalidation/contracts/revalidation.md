# Historical revalidation contract

Only the original version/source/manifest tuple can elect the v1.0.1 profile. Source proof verifies complete exact tracked bytes without executing selected scripts. Receipt checks independently retain original Windows first-use, relocation, GUI/native, distribution, signing and installer lifecycle evidence. MSI acceptance requires the exact anchored original file and original installer/payload declarations. Changed tables or embedded streams fail even if receipt digests change.

Candidate loading, published retrieval and public verification share the selected profile. Nested verification defaults to modern requirements and cannot opt out using a receipt version alone. Current or unknown candidates require modern terminals and coordinated setup. Preserve existing v1.0.0 platform handling.

No tag, source, published asset or release metadata is mutated. Documentation/build source is selected separately from trusted running tooling. Verification reads bytes and does not install or launch historical binaries.
