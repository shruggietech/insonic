# Research

Windows ExifTool filename transport uses UTF-8 stdin arguments with explicit filename charset, following the upstream [Windows Unicode filename contract](https://exiftool.org/exiftool_pod.html#WINDOWS-UNICODE-FILE-NAMES). The installed-path campaign exposed capture failures before ledger execution; source and package checks continue to require successful captures, without an ASCII path restriction.

- Decision: derive accepted paths/options from installed help generated by cmd/insonic/commands.go. Rationale: one parser authority, existing help parity tests. Rejected: another command registry or product inventory command.
- Decision: distinguish invocation checks from asserted outcomes. Rationale: cli_help_examples.py currently labels some immediate non-null results succeeded and misses option coverage. Rejected: treating help or broad expected-code sets as semantic proof.
- Decision: index existing eight regression modules, documented trainer workflows and licensed media manifest. Rationale: their byte/timing/HTTP/credential checks already exist. Rejected: recreating old audit scratch inputs or adding a second journey.
- Decision: bind to CLI hash and existing verified package inventory; rename owned library/install roots for missing Unicode destination coverage. Rationale: extracted paths and media names already contain Unicode, while those destinations do not.
- Decision: assert joined provider/documented threads stop before claiming cleanup. Rationale: current joins omit the live-thread check present in media qualification.
- 2026-10-22: Hosted Windows package diagnostics isolated partial capture to ExifTool while FFprobe succeeded. The pinned launcher imports ANSI module/path APIs. Its [upstream launcher source](https://oliverbetz.de/pages/Artikel/Portable-Perl-Applications) confirms that path handling. On private copies of the exact pinned launcher, process-local Legacy mode succeeded in an ASCII directory and failed to find Perl in a non-Latin directory; UTF-8 mode succeeded in that same non-Latin directory. The host's default UTF-8 code page had masked the hosted failure. Following [Microsoft's activeCodePage manifest contract](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests), transform only the packaged launcher with a reproducible UTF-8 process manifest before signing. Preserve original bytes, resource leaves, unsigned hashes and the recipe in corresponding sources; independently verify the transformation. Reject ASCII-only installation restrictions, global locale changes, dependency upgrades and suppressed capture assertions. Existing setup resource writing is shared rather than duplicated.
- 2026-10-22: The next hosted run completed media import, then reached LadybugDB's unavailable response under a non-Latin library parent. A real native graph test with an existing mixed-Unicode parent failed under a private Legacy process manifest and passed under UTF-8, including close/reopen and exact-path existence. Apply the same process-local contract to Windows product executables; retain mandatory packaged queries. That run separately logged a five-minute npm advisory request and a 180-second site-install timeout; the bulk advisory service subsequently returned HTTP 200. Preserve fixed input and qualification deadlines; bound npm fetches to 15 seconds with at most two retries while explicitly retaining advisory auditing, then retry the fresh workflow after the product correction. The prior five-minute default request could exceed the unchanged 180-second operation limit.
