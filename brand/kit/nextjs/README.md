# insonic: Next.js binding

GENERATED by shruggie-brandbuilder. Regenerate this binding after changing the source spec.

Use the registry route if your project uses Next.js, Tailwind v4, and shadcn.
Other sites can use the kit's vanilla CSS and asset files directly.

## Install into a project

```bash
npx shadcn@4.21.0 init
npx shadcn@4.21.0 registry add @insonic=https://brand.shruggie.tech/insonic/brand/r/{name}.json
npx shadcn@4.21.0 add @insonic/theme
npm i next-themes
```

The public `registry.json` is a discovery catalog. The CLI installs the individual
`/r/{name}.json` items. The catalog does not install local fonts.

The parent kit's `color-roles.json` records formal identity combinations,
artwork references, interface cue meanings, and accessible pairings.

Confirm installation by finding light and dark `--background` in your
global stylesheet and the requested component files under `components/`.

## Install bundled local fonts

Copy `nextjs/fonts.ts` and the kit's `fonts/` tree together into your project,
keeping their relative paths. Import `fontVariables` from `fonts.ts` and apply
it to `<html>`. Inspect the copied face paths before building. These fonts
never require `next/font/google` or a runtime font request.

## Or wire it by hand

Copy `globals.css` over your own, keep `nextjs/fonts.ts` one level below `fonts/`,
copy `providers.tsx`,
apply `fontVariables` to `<html>`, wrap the tree in `<Providers>`.

## Rules that outlive this file

- Dark is the default. Light is a reading surface for docs and blog.
- Never set the bright accent as text on a light surface. The light block
  already substitutes the accessible variant.
- Never request a font weight the shipped face does not contain.
- Never fetch fonts at build time. `fonts.gstatic.com` is blocked in the
  sandbox and the failure only surfaces after the CSS step appears to work.
