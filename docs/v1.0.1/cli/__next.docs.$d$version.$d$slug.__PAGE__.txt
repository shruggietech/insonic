32:T3866,<h1 id="cli-invocation-and-results">CLI invocation and results</h1>
<p>Run <code>insonic --help</code> for the installed command inventory. Every command and group accepts <code>-h</code>, <code>--help</code> and <code>help COMMAND</code>. A group without an operation displays its commands. Help succeeds before workspace discovery, input-file reading, credential input, provider access, runtime startup or mutation. <code>--version</code> is an alias for <code>version</code>.</p>
<pre tabindex="0" aria-label="Code example"><code class="language-text">insonic help media import
insonic settings set --help
insonic models speaker list -h
</code></pre>
<h2 id="arguments-and-json-files">Arguments and JSON files</h2>
<p>Global <code>--workspace DIRECTORY</code>, <code>--request-id UUID</code> and <code>--json</code> options can appear before or after command options. Scalar options appear once. Value options accept either <code>--name VALUE</code> or <code>--name=VALUE</code>; Boolean switches take no value. A value is consumed as a whole token, including a value beginning with <code>--</code>. Repeatable <code>--known-speaker</code> import selectors and roster <code>--speaker</code> selectors retain every occurrence. Contextual help lists each command's accepted options, required operands, enums, ranges, defaults and repeatability.</p>
<p><code>--</code> ends option and help recognition. Following filenames or text remain literal data. For example, <code>insonic search -- --json</code> searches for the text <code>--json</code>, and <code>insonic catalog export -- --help</code> writes the explicitly selected filename <code>--help</code>. Help flags that precede the terminator resolve before effects.</p>
<p><code>--input FILE</code> reads a complete JSON file. Contextual help prints an illustrative JSON-file template and its applicable packaged input contract, including optional fields and conditions. Replace illustrative UUIDs, revisions, paths and model selections with current values. Input files do not contain an IPC request envelope. A model register/acquire command instead accepts a model-manifest file as its operand. Structured definitions and model manifests retain their own documented contracts.</p>
<pre tabindex="0" aria-label="Code example"><code class="language-text">insonic --workspace LIBRARY settings show --json
insonic --workspace LIBRARY settings set --input settings.json --json
insonic --workspace LIBRARY models list --speaker SPEAKER_UUID --limit 100 --json
insonic --workspace LIBRARY work wait WORK_UUID --timeout-ms 30000 --json
</code></pre>
<p><code>models base</code> aliases the base-model commands; <code>models download</code> and <code>models base download</code> alias acquisition. <code>models list --speaker UUID</code> uses the same speaker-model listing as <code>models speaker list --input FILE</code>. Omit <code>--after</code> for its initial page. <code>search</code> constructs a normalized <code>query run</code> input; <code>query native</code> constructs a native <code>query run</code> input using <code>--dialect</code>, <code>--file</code> and optional <code>--parameters</code> files.</p>
<p>Catalog migration/export/restore and portable backup operations are advanced maintenance commands. Mutating maintenance requires exclusive workspace ownership. <code>runtime serve</code> is the internal noninteractive owner normally launched by clients; contextual help keeps its syntax available.</p>
<h2 id="optional-first-run-setup">Optional first-run setup</h2>
<p><code>setup location [PATH]</code> previews an editable location without creating it. <code>setup draft show</code> and <code>setup draft save --input FILE</code> read/save the private pre-workspace draft, including its expected revision, chosen path and normalized backend plan. <code>setup provision</code> explicitly creates the saved fresh-library selection through the existing protected bootstrap channel; it accepts <code>--secret-input</code> and <code>--credential-backend native|vault|session</code>. Backend selection precedes provisioning; existing libraries retain their selected profiles.</p>
<p>After selecting a workspace, <code>setup show</code>, <code>setup save --input FILE</code> and <code>setup readiness</code> read progress, save typed journey metadata and request current task checks. <code>settings setup</code> aliases the readback/reopening operation. Journey saves do not enqueue downloads, create pipelines or import media. Copy the returned state and current stage observation proofs, save with the observed revision and retain the same immutable input/request UUID to reconcile an unknown response. Changed input or a stale revision conflicts without overwriting newer choices. See <a href="/docs/v1.0.1/setup/">first-run setup</a> for the complete five-stage journey and executable local-default procedure. All setup commands are noninteractive and support the normal result envelopes.</p>
<h2 id="local-worker-and-model-setup">Local worker and model setup</h2>
<p>The shared <code>workers catalog|inspect|plan|setup</code>, <code>models defaults|prepare</code> and <code>processing readiness</code> operations accept the contextual JSON templates. Setup and acquisition use normal durable work. See <a href="/docs/v1.0.1/processing-setup/">local processing setup</a> for the complete preview, election, wait, model and pipeline procedure.</p>
<h2 id="human-results-and-work-progress">Human results and work progress</h2>
<p>Commands without <code>--json</code> print readable named fields, empty states, warnings and supported next commands. Human results preserve exact numeric tokens but are a display, rather than an automation contract: at most 128 lines, 64 items per collection, six levels of detail and 512 UTF-8 bytes per displayed value. Use JSON and the applicable paging operation for complete detail. Terminal controls in values are replaced with spaces.</p>
<p>Document pages display readable UTF-8 text instead of base64. Binary pages and omitted document detail identify the JSON/page retrieval route. Materialized paths include publication and lease identities with release/renew commands. Registration and startup describe configured resources; they do not establish provider authentication or acoustic inference readiness.</p>
<p><code>work wait</code> shows changed durable state, stage and available item/file counts on an interactive human terminal. It does not invent percentages. Redirected human output and JSON contain only the final or last observed result. A timeout or interrupted wait leaves durable work running; inspect, wait or cancel the same work ID. Interrupted or failed work exposes its retry route.</p>
<p>Accepted media with unresolved date observations remains useful and successful unless an item actually failed. Human results identify the affected item/media, date state and inspection/correction commands. Date-only precision is not itself an error. Large results identify result paging instead of claiming omitted items have no warnings.</p>
<h2 id="diagnostics">Diagnostics</h2>
<p>Global <code>--verbose</code> adds request/workspace identifiers. <code>--debug</code> also adds generated terminal progress detail and defaults elected logs to debug severity. <code>--quiet</code> suppresses informational human results and progress while retaining warnings/errors. Quiet cannot combine with verbose/debug. All three preserve JSON envelopes and exit meanings.</p>
<p><code>--log-file FILE</code> explicitly elects a private JSONL diagnostic file; its directory must exist. <code>--log-level error|warn|info|debug</code> selects severity, with info as the normal default. The log retains timestamps, request/workspace UUIDs, operation, generated code/reason, work state and elapsed time. It excludes arguments, input documents, credential values, protected stdin, prompts, endpoints, environment values and arbitrary tool/provider output.</p>
<p>Each data file is bounded to 1 MiB, with at most two predecessors (<code>FILE.1</code> and <code>FILE.2</code>). A private empty <code>FILE.lock</code> coordinates ownership; concurrent commands must elect separate files. Files use current-user Windows ACLs or Unix mode 0600. Opening or securing an elected log fails before command effects; later logging/output delivery failures return a nonzero status and do not undo accepted work. No log is required when logging was not elected.</p>
<p>Hidden runtime startup reports readiness or a fixed classified failure through a bounded 4096-byte internal channel, with a shared ten-second startup deadline. Early child exit and malformed reports fail promptly. Profile/control-directory, ownership, endpoint, credential bootstrap and application/catalog failures give supported corrections without repeating protected input. A competing cold client joins the live owner; the detached owner survives its launching client and retains existing idle/work lifetime.</p>
<h2 id="machine-output">Machine output</h2>
<p>Every <code>--json</code> result uses the current <code>runtime-response</code> envelope. Help and version have structured results; local initialization, configuration and maintenance use the same envelope as live runtime operations. Request IDs correlate responses, and workspace/runtime IDs appear when known. Integers remain JSON integers with their exact decimal value, including signed 64-bit clocks and identifiers above JavaScript's exact Number range. Consumers must use an exact-integer parser for such fields.</p>

<p>A failed wait response retains both its last structured <code>result</code> and its top-level <code>error</code>. Inspecting failed work through <code>show</code> or <code>results</code> succeeds as an inspection operation; the work's own state and error remain in the result. A wait timeout reports <code>unavailable</code> and leaves durable work running. Encoding or writing output must succeed before a command reports success.</p>
<h2 id="dates-credentials-and-durable-failures">Dates, credentials and durable failures</h2>
<p>An entered recording timestamp containing <code>Z</code> or a numeric offset determines its instant when the timezone policy was omitted or <code>local</code>. Admission captures the local zone for unqualified wall times and preserves that implicit provenance through replay. An explicitly selected timezone still checks agreement with an entered offset. Date-only precision, unresolved folds/gaps and original literals remain inspectable; no midnight or offset is invented for an unknown time.</p>
<p>Vault add/replace/delete/unlock/load commands use bounded JSON on protected stdin. Deletion requires a passphrase consistently with a stopped, locked or unlocked runtime. Native/session deletion needs no stdin. See <a href="/docs/v1.0.1/secrets/">credential commands</a> for protected input and credential-value forms.</p>
<p>Durable work retains generated classified causes across reload, result paging and snapshot restore. Conflicts, unavailable dependencies, checksum mismatches, input limits, acquisition deadlines and cancellation remain distinguishable. Per-item errors remain in item results; heterogeneous failed causes use <code>mixed_item_failure</code>. Historical generic <code>operation_failed</code> records keep their original meaning and receipts. No raw provider body or child output becomes a durable error message.</p>
<p>The current reader supports persisted insonic 1.0.0 documents alongside the current document version. Existing workspace/profile identities, revisions, accepted document/model bytes and hashes remain intact. New transport envelopes and package identities use the current release version. A new portable backup uses the current envelope while retaining its historical source profiles, immutable model documents and proofs. Older product versions are not promised to understand newly classified causes or current response shapes.</p>
<p>Importing a supported historical tools file with <code>media tools FILE</code> or <code>processing tools FILE</code> creates a current-version setting while preserving the source file and executable integrity pins. Direct <code>settings set</code> payloads use the current input contract.</p>
<p>A supported historical media-import manifest is normalized in the request copy after admission; the source file remains unchanged. Model register/acquire retains an immutable historical manifest's declared version and content digest, using its packaged historical schema inside the current request envelope.</p>
<h2 id="backend-and-service-setup-commands">Backend and service setup commands</h2>
<p><code>workspace plan --input FILE</code> constructs a complete nonsecret plan without a workspace. <code>workspace preflight DIRECTORY --input FILE [--secret-input]</code> reports bounded readiness without provisioning. <code>workspace provision DIRECTORY --input FILE [--credential-backend native|vault|session] [--secret-input]</code> explicitly initializes a fresh target. Contextual help includes the complete backend-plan schema. Protected input comes from stdin, never command-line values. Save the generated configuration and reuse it with the same credential backend for retry reconciliation. Completed retries verify the retained receipt and persisted credential selection.</p>
<p><code>query services [--input FILE]</code> inventories and probes candidate Ollama metadata without adopting routes or loading models. <code>query assistance-test --input FILE</code> elects a synthetic task for the exact saved settings_revision and may load the model. Existing <code>query assistance-show</code>, <code>query assistance-set</code> and <code>query assist</code> support both insonic-http and native ollama adapters. <code>--json</code> returns the shared versioned envelopes.</p>
