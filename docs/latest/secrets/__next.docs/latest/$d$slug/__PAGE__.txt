32:T3700,<h1 id="credential-commands">Credential commands</h1>
<p>The source-buildable CLI and shared desktop bridge configure credentials independently of catalog access. This lets you provision a PostgreSQL credential before the runtime opens that catalog. Native persistent storage, an encrypted vault and explicit session credentials share the same workspace-scoped UUID references. <a href="/docs/v1.0.1/security/">Credentials and data access</a> defines routing and access boundaries.</p>
<h2 id="choose-the-store">Choose the store</h2>
<pre tabindex="0" aria-label="Code example"><code class="language-sh"><span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials <span class="hljs-keyword">select</span> native <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials <span class="hljs-keyword">select</span> vault <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials <span class="hljs-keyword">select</span> session <span class="hljs-attr">--json</span>
</code></pre>
<p>Choose one backend for the workspace. The selection persists in the private control directory, without credential values. Native storage uses Windows Credential Manager or Linux Secret Service. A locked or unavailable service returns a fixed rejected/unavailable result; it does not display an unlock prompt, start a session bus or switch to another backend. Unlock the operating system's service through its own controls, or explicitly select the vault/session alternative.</p>
<p>Credential IDs are UUIDs scoped to the workspace identity. Configuration, catalog snapshots, import/model manifests and jobs retain only those references. Copying encrypted vault bytes into a different workspace does not grant access because the workspace identity is authenticated with the ciphertext.</p>
<h2 id="enter-and-replace-values">Enter and replace values</h2>
<p><code>add</code> and <code>replace</code> read one bounded JSON object from standard input. There is no credential-value command-line option. <code>INPUT_PRODUCER</code> below denotes your protected input source, not an insonic command. The desktop <code>Credential</code> bridge passes newly entered input through the same command service.</p>
<pre tabindex="0" aria-label="Code example"><code class="language-sh"><span class="hljs-variable">INPUT_PRODUCER</span> | <span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials add <span class="hljs-variable">CREDENTIAL_UUID</span> <span class="hljs-attr">--json</span>
<span class="hljs-variable">INPUT_PRODUCER</span> | <span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials replace <span class="hljs-variable">CREDENTIAL_UUID</span> <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials status <span class="hljs-variable">CREDENTIAL_UUID</span> <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials delete <span class="hljs-variable">CREDENTIAL_UUID</span> <span class="hljs-attr">--json</span>
</code></pre>
<p>The protected input object contains <code>value</code>. A string stores its UTF-8 bytes; an object stores its JSON representation for an adapter that expects structured authentication. These examples describe the input shape and contain placeholders:</p>
<pre tabindex="0" aria-label="Code example"><code class="language-json"><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;value&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;NEWLY_ENTERED_KEY&quot;</span><span class="hljs-punctuation">}</span>
</code></pre>
<pre tabindex="0" aria-label="Code example"><code class="language-json"><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;value&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;username&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;DATABASE_USER&quot;</span><span class="hljs-punctuation">,</span><span class="hljs-attr">&quot;password&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;NEWLY_ENTERED_PASSWORD&quot;</span><span class="hljs-punctuation">}</span><span class="hljs-punctuation">}</span>
</code></pre>
<pre tabindex="0" aria-label="Code example"><code class="language-json"><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;value&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;access_key&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;ACCESS_KEY&quot;</span><span class="hljs-punctuation">,</span><span class="hljs-attr">&quot;secret_key&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;SECRET_KEY&quot;</span><span class="hljs-punctuation">,</span><span class="hljs-attr">&quot;session_token&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;OPTIONAL_SESSION_TOKEN&quot;</span><span class="hljs-punctuation">}</span><span class="hljs-punctuation">}</span>
</code></pre>
<p><code>add</code> rejects an existing registration or a native credential left by an interrupted registration write. <code>replace</code> requires an existing registration or native credential and changes it only through the explicit replacement operation. Explicit replacement or deletion can reconcile that interrupted native registration. A credential value is limited to 2,048 bytes, within the Windows native-storage limit; each selected store accepts at most 256 registrations. Unknown fields, duplicate JSON keys, malformed input and oversized values fail with fixed errors that do not repeat the supplied input.</p>
<p>Status returns the credential ID, selected backend and <code>configured</code>, <code>locked</code>, <code>missing</code> or <code>rejected</code>, with <code>stored</code>, <code>locked</code> and <code>authentication: &quot;not-checked&quot;</code> facts. It checks the managed nonsecret registration information without retrieving a saved value. <code>configured</code> is registration status; resolving the credential and using the selected adapter establishes whether the saved value exists and whether the provider accepts it. An external deletion from the operating system's credential store may therefore become visible only during adapter use.</p>
<p>Deleting a credential leaves its references in profiles and other configuration.
Subsequent credential resolution and new authenticated connections report
unavailable. Established provider sessions follow the provider's lifetime and
revocation behavior; deleting a local reference does not revoke an authenticated
PostgreSQL server session. S3 resolves the selected reference for each subsequent
request. Reconfigure or replace the selected credential to restore access.
Native deletion uses no input; vault deletion needs its passphrase through the
protected input object.</p>
<h2 id="encrypted-vault">Encrypted vault</h2>
<p>Vault input adds a <code>passphrase</code> string to the same protected object:</p>
<pre tabindex="0" aria-label="Code example"><code class="language-json"><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;value&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;username&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;DATABASE_USER&quot;</span><span class="hljs-punctuation">,</span><span class="hljs-attr">&quot;password&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;NEWLY_ENTERED_PASSWORD&quot;</span><span class="hljs-punctuation">}</span><span class="hljs-punctuation">,</span><span class="hljs-attr">&quot;passphrase&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;NEWLY_ENTERED_VAULT_PASSPHRASE&quot;</span><span class="hljs-punctuation">}</span>
</code></pre>
<p>The vault fixes Argon2id version 19 at 64 MiB, three iterations, four lanes and a 32-byte derived key. AES-256-GCM authenticates the encrypted credential map and its format, KDF parameters, workspace ID and nonsecret credential-ID list. Each vault has a random 16-byte salt; each update has a fresh 12-byte nonce. The implementation uses maintained <a href="https://pkg.go.dev/golang.org/x/crypto/argon2">Go Argon2</a> and <a href="https://pkg.go.dev/crypto/cipher#NewGCM">authenticated-encryption</a> libraries. Untrusted files cannot select a larger work factor or downgrade the algorithms.</p>
<p>The private control directory stores ciphertext and nonsecret selection/registration data. Updates lock exclusively, reread the current map and atomically replace a synced file, so concurrent owners do not discard each other's changes. The passphrase and derived key remain in process memory and are cleared when the manager closes; neither is saved beside ciphertext. Credential encryption applies to these credentials, while media/artifact encryption follows the selected storage configuration.</p>
<pre tabindex="0" aria-label="Code example"><code class="language-sh"><span class="hljs-variable">INPUT_PRODUCER</span> | <span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials unlock <span class="hljs-attr">--json</span>
</code></pre>
<p>For <code>unlock</code>, send <code>{&quot;passphrase&quot;:&quot;NEWLY_ENTERED_VAULT_PASSPHRASE&quot;}</code> through standard input. The runtime accepts the passphrase through its protected bootstrap channel and retains the unlocked manager for that owner's lifetime. After the runtime exits, unlock again before an operation requiring vault credentials. Status of an existing saved registration without an unlocked manager reports <code>locked</code> with <code>stored: true</code>; its value remains persisted. A missing registration remains missing. Unlock/load success identifies the current runtime-owner lifetime and does not prove provider authentication. A wrong passphrase, tampered ciphertext or unsupported envelope returns unavailable without exposing its contents.</p>
<h2 id="explicit-session-credentials">Explicit session credentials</h2>
<p>Session values remain in the runtime owner's memory and disappear when it exits. Load a UUID-to-value mapping through protected input:</p>
<pre tabindex="0" aria-label="Code example"><code class="language-json"><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;session&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;CREDENTIAL_UUID&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;username&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;DATABASE_USER&quot;</span><span class="hljs-punctuation">,</span><span class="hljs-attr">&quot;password&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;NEWLY_ENTERED_PASSWORD&quot;</span><span class="hljs-punctuation">}</span><span class="hljs-punctuation">}</span><span class="hljs-punctuation">}</span>
</code></pre>
<pre tabindex="0" aria-label="Code example"><code class="language-sh"><span class="hljs-variable">INPUT_PRODUCER</span> | <span class="hljs-title">insonic</span> <span class="hljs-attr">--workspace</span> <span class="hljs-variable">WORKSPACE</span> credentials load <span class="hljs-attr">--json</span>
</code></pre>
<p>Once loaded, <code>add</code>, <code>replace</code>, <code>delete</code> and <code>status</code> operate on that live manager. A standalone short-lived manager does not claim that an ephemeral change was persisted. The explicitly selected <code>INSONIC_SESSION_CREDENTIALS</code> environment mapping remains available for automation, using UUID keys and string/object values. It is consulted only for a workspace that selected session mode; a native/vault failure never falls back to that mapping. Loading a new explicit mapping replaces the current session input rather than persisting it.</p>
<p>The runtime's normal idle shutdown ends vault unlocks and session credentials. Long-running configured work keeps the owner alive for its active operations. CLI and desktop responses contain status information; neither provides a command to display a saved value.</p>
<h2 id="initial-backend-credentials">Initial backend credentials</h2>
<p>Backend provisioning is available before a catalog owner exists, so PostgreSQL credentials can be supplied before its first connection. Backend plans contain only opaque references. Newly entered values use protected stdin or the native desktop bootstrap channel, with a purpose-specific form and automatically generated IDs. Preflight uses these transient values without registration. Explicit provisioning registers native/vault values or loads the session manager, then opens the selected catalog. Credential registration and successful provider authentication remain distinct.</p>
<p>Choose native, vault or session explicitly for provisioning. Vault requires its protected passphrase; session values last in the owner and must be reloaded after restart. Plan/status/diagnostic responses never return saved values. Local Ollama requires no invented key; optional bearer credentials use the same protected service.</p>
