33:T906f,<h1 id="speakers-and-terminology">Speakers and terminology</h1>
<h2 id="local-voices-and-known-speakers">Local voices and known speakers</h2>
<p>A diarization voice belongs to one recording. Its local token occurs in the current embedded Cue JSON document; it is not a global person ID. The same person in another recording receives another local speaker token. Imported tokens retain their exact upstream-valid values. Native subtitle labels and mentioned names remain source observations, independent of that identity. A catalog speaker is a stable user-facing identity with a canonical name, active state and revisioned aliases.</p>

A mentioned person, quoted statement, scene participant and speaking voice are different observations. Unsupported identity remains unresolved and does not block valid source-level operations. Model confidence is a diagnostic, not proof of identity.</p>
<p>Known-person corrections update the external recording/token mapping without rewriting subtitle text or document bytes. Mapping rows bind current document identity and expected revision. A removed local speaker token cannot retain an active mapping. Other records cannot establish another list of assignments under a voice, segment or attribution-revision name.</p>
<h2 id="reference-only-speaker-audio">Reference-only speaker audio</h2>
<p>A current segment record refers to recording ID, document digest, cue ID and local speaker token, with an optional managed clip reference. It stores no copied interval, channel, known-person assignment or attribution array. Query and playback resolve the interval from current embedded assignments and the recording's source map. Untimed participation does not provide an exact clip interval, and uncovered acoustic speech does not gain invented subtitle cues.</p>
<p>The speaker corpus spans all current library recordings. A source can contribute overlapping voices, and deduplication uses original source/cue evidence rather than counting repeated processing as independent speech. Lazy extraction uses verified source bytes and explicit transform/time mapping. A clip is derived current data and cannot retain an obsolete assignment as an alternative authority.</p>
<p>Replacing the current document removes stale segment/membership references and invalidates dependent evidence and prepared corpus data. Mapping correction preserves the current document/segments while invalidating dependent selection/preparation. Physical cleanup retires removed managed clips/manifests after leases and reference barriers allow deletion. Source media and supplied subtitles remain immutable.</p>
<h2 id="identity-model-lineage-and-correction">Identity, model lineage and correction</h2>
<p>Names and aliases use explicit IDs, language/scope and provenance. Equal name text does not merge people automatically. Shared commands persist canonical names and alternate spellings with language, scope, provenance and active state. Inactive identities and spellings are excluded from active recognition context. Broad merge/split and similarity retain separate delivery contracts; they use the same current-reference rule when delivered.</p>
<p>A merge or split updates current mappings and invalidates affected corpus preparation. Completed model weights/checkpoints can retain originating source IDs, hashes, run identity and staleness diagnostics. They do not preserve an old transcript or assignment list. An invalidated corpus cannot be used again without resolving current evidence and rebuilding its preparation. <a href="/docs/v1.3.1/voice-models/">Speaker audio and voice models</a> defines those relationships.</p>
<p>Configured model-generated assignments can be applied automatically when their contracts validate. Users can correct them without reviewing every voice or segment. Optional embeddings and model comparisons name their actual input/model provenance; a prediction derived from an earlier assignment is not independent corroboration.</p>
<h2 id="specialized-terms">Specialized terms</h2>
<p>The terms contract covers stable IDs, canonical spelling, variants, language/context, active state, revision and optional explicit speaker/alias links. Explicitly selected active speaker names and relevant aliases join active general terms and matching language/context terms when compiling supported recognition hints. Leaving the speaker selection empty does not elect every catalog identity. IDs govern the join, not accidental text equality.</p>
<p>Compile and deduplicate hints deterministically within the chosen recognizer's supported UTF-8 byte budget. The compiled result records source revisions separately from the digest of the canonical effective hint array, and reports unsupported, duplicate, inactive, filtered or budget-omitted candidates. Equivalent effective hints retain the same digest even when source provenance changes. Local faster-whisper supports a 200-byte joined hint budget; a hosted worker declares its supported budget up to 8192 bytes. A term is recognition context, not evidence that a named person spoke. A vocabulary rerun replaces the current subtitle result after acceptance; guided/unguided alternatives and obsolete text are not retained as selectable transcripts.</p>

When no language filter is supplied, compilation uses that recognizer's language. Pipeline inspection applies the same rules to its effective saved or overridden stage, so its hint preview matches a generated recognition election. Compilation runs no model and proves no speaking identity. Desktop Pipelines, Speakers and Terms controls use these operations. Corrections use the same IDs, expected revisions and current-reference validation in every client.</p>
<h2 id="declared-recording-rosters">Declared recording rosters</h2>
<p>Add and remove require at least one speaker reference in every interface; blank edits fail without changing roster authority. Replace accepts an explicit empty list, and clear declares an empty roster.</p>
<p>A declared roster expresses intended speaker context for a recording, including one with no transcript. Its header anchors to the stable library recording ID; each unique membership references an existing centralized speaker ID. It stores no copied names, profiles or assignments. An undeclared roster has revision zero; an explicitly empty roster has a positive header revision. Names and active/inactive states are read from the current speaker catalog.</p>

<p>Mutations compare the independent roster revision and reconcile repeated request IDs. Set no-ops preserve the roster revision. References resolve by UUID, unique exact canonical name or active alias; ambiguity and inactive new elections fail. Use <code>name:</code> for a UUID-shaped name. Existing inactive members remain visible and removable by ID. Membership is bounded to 1,000 speakers and selectors to 512 UTF-8 bytes. An empty replacement or clear declares an empty roster.</p>
<p>Initial known-speaker references resolve once when work is queued; later alias edits cannot retarget the frozen IDs. Audio and membership publish in one current transaction, leaving no orphan roster on failure. Transcript or mapping edits preserve membership. Audio replacement explicitly retains or clears an existing roster. Portable snapshots validate parent identities, unique membership, revisions and accepted current proofs on SQLite/PostgreSQL. Graph projection exposes separate <code>declared-speaker</code> context edges.</p>
<p>The desktop Library exposes initial roster input, a current roster table and add/remove/replace/clear controls using the displayed revision. A conflict refreshes current roster authority and reports the failed election. Declaring membership alone does not assign a transcript voice, create training evidence or infer how many speakers actually spoke. An explicit <a href="/docs/v1.3.1/voice-models/#roster-constrained-matching">matching election</a> compares existing voices against compatible exact profiles for active roster members. Matching preserves manual corrections and accepted contextual mappings and can leave a voice unknown or ambiguous. Automatic results never enter independently confirmed training evidence.</p>

<h2 id="contextual-speaker-discovery">Contextual speaker discovery</h2>
<p>Discovery extracts current, inspectable hypotheses from a recording's transcript through an explicitly enabled HTTP or Ollama provider. It joins exact names and active aliases without merging equal spellings, retains language, role and relationship observations, and separates direct introductions from mentions and quotations. Current manual mappings remain authoritative, including mappings to inactive identities; those inactive identities are excluded from provider candidate context. Discovery and resolution do not change mappings, create speaker identities, enroll training data or run acoustic matching.</p>
<ol>
<li>Select an enabled assistance configuration in <code>discovery.json</code>. An omitted configuration uses the saved assistance provider; it must already be enabled. The example elects a local structured HTTP endpoint and a model named <code>local-model</code>.</li>
<li>Run <code>insonic speakers discover RECORDING_ID --input discovery.json --json</code> and retain the returned work ID.</li>
<li>Use <code>insonic work wait WORK_ID --json</code>, or inspect/cancel the work through the ordinary durable-work commands.</li>
<li>Read <code>insonic speakers hypotheses RECORDING_ID --json</code>. Review coverage, evidence references, alternatives and reasons.</li>
<li>To recompute decisions using the same current evidence, save the returned aggregate revision as <code>expected_revision</code> in <code>resolution.json</code> and run <code>insonic speakers resolve RECORDING_ID --input resolution.json --json</code>.</li>
</ol>

<p>Provider output must use current selected cue and voice IDs and exact source quotes. The runtime rejects duplicate JSON keys, unknown fields, invented intervals/person IDs, foreign citations, unsupported observed names and oversized responses. Accepted references store UTF-8 byte offsets and quote digests rather than copied transcript text. Partial-cue or multiple-voice citations do not establish direct attributable identity. Citation checks establish source membership and current authority; they do not prove that the provider classified every introduction, quotation or relationship correctly. Model errors remain inspectable hypotheses.</p>
<p>Independent contextual roots come from current original-source identity, stream/channel and mapped intervals. Duplicate and overlapping source evidence counts once. Missing track/timing provenance is conservatively dependent. Acoustic evidence must bind a succeeded matching work record, its accepted journal receipt, current roster/profile/output/dataset authority and current independently grounded enrollment references that do not overlap the evaluated voice. Matching's own automatic mapping update is accounted for when checking freshness. Automatic assignments and derived predictions cannot independently corroborate themselves. Unavailable or stale acoustic evidence is explicit and does not prevent contextual extraction.</p>
<p>The default selection is the first 100 current cues, with at most four provider calls and 128 observations. Caps are 500 cues, 20 calls and 512 observations; each observation has at most 16 references. Provider context is bounded to 25 cues and 32 KiB per call, responses to the configured limit up to 512 KiB, and the accepted aggregate to 1 MiB. All calls, source checks and acceptance share one configured provider timeout, at most 60 seconds. A configured call limit can leave an explicit omitted-cue count; a failed chunk, malformed response, cancellation, changed authority or exceeded observation/byte budget publishes no partial aggregate. The previous aggregate remains current only while its original source authority still matches.</p>
<p>Current recording, mapping, identity/alias, roster and relevant model-lineage changes invalidate affected discovery evidence. Invalidation removes obsolete hypothesis content and leaves compact digest-only journal proofs; replay cannot resurrect it. Schema-12 SQLite/PostgreSQL catalogs and portable snapshots enforce the same current-authority checks.</p>
<p>These advanced commands use the shared runtime and desktop <code>Operate</code> bridge. Dedicated discovery controls are not yet present in the desktop UI; use the CLI included with the desktop package. The same runtime also exposes the application and unattended workflow operations below.</p>
<h2 id="apply-retract-and-run-configured-speaker-work">Apply, retract and run configured speaker work</h2>
<p>Use <code>speakers apply RECORDING_ID --input apply.json</code> with <code>{&quot;expected_revision&quot;:42}</code>, replacing 42 with the current discovery revision. Application only admits registered, active identities supported by independently attributable contextual introductions. It recomputes support without manual mappings or acoustic predictions as corroboration. Equal-name ambiguity, mentions, quotations, circular matches and contradictory decisions remain unapplied. Current manual mappings always win. Application returns counts and exact mapping revisions, retains digest/offset/source-root lineage, and invalidates the consumed discovery aggregate when mappings change.</p>
<p>A contextual mapping has <code>origin: contextual</code>; acoustic predictions retain <code>origin: automatic</code>, and an explicit owner correction uses <code>origin: manual</code>. Repeating an accepted request ID returns its receipt without recreating a retracted or corrected mapping. A fresh unchanged application preserves the mapping revision and corpus. Applying a conflicting interpretation retracts the previous contextual mapping for that voice. An unknown or ambiguous rerun preserves an otherwise current accepted mapping without supplying new enrollment evidence.</p>
<p>Use <code>speakers retract RECORDING_ID --input retract.json</code> with the current recording revision and exact contextual mapping IDs/revisions:</p>

<p>Retraction is atomic and cannot remove a newer mapping or an owner correction. Source/document replacement, identity/alias edits and retraction invalidate affected contextual membership, datasets, current profile usability and graph projections. Completed model bytes remain available by exact version; their historical origin does not grant current enrollment authority.</p>
<p>For unattended execution, elect a <a href="/docs/v1.3.1/pipelines/#configured-speaker-workflow">speaker workflow</a> with <code>speakers run RECORDING_ID --input workflow.json</code>. The durable parent coordinates discovery, application and optional enrollment through existing child jobs. It releases its worker slot while waiting. Cancellation revokes unfinished children; retry and restart retain completed stages, exact model/provider choices and original profile revision fences. A stale source election requires a fresh request. No per-item confirmation is required. Human output separates hypotheses, contextual mappings and acoustic profiles; <code>--json</code> retains full counts, exclusions, lineage and child IDs.</p>
