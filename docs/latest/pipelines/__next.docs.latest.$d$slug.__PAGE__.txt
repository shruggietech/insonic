32:Tbbba,<h1 id="pipelines-and-adapters">Pipelines and adapters</h1>
<p><a href="/docs/v1.1.0/processing-setup/">Local processing setup</a> prepares optional engines and models and reports prerequisites for a selected pipeline. Settings can save a pipeline with exact builtin models and automatic NVIDIA preference; saving it does not begin inference. New local requests default to <code>auto</code>, while explicit <code>cpu</code> stays CPU. <code>auto</code> and <code>cuda</code> can retry once on CPU for classified CUDA failures, with visible device provenance.</p>
<h2 id="configured-work-and-current-results">Configured work and current results</h2>
<p>A pipeline declares elected models, adapters, device/resource settings and routing. Saved definitions advance revisions and accepted work retains its elected configuration; processing does not retain alternative transcripts or assignment stores. Changing defaults affects future work. Rerunning a stage replaces the current result after validation and fenced acceptance. Once routing is configured, normal work proceeds without per-item approval or silent provider fallback.</p>
<p>Saved Local, Connected and Custom pipelines use stable IDs and expected-revision updates. Local selects both local workers, Connected selects both hosted workers, and Custom supports an explicit mix. The stored values are <code>local</code>, <code>connected</code> and <code>custom</code>. Each stage declares its adapter contract, exact managed local model or remote model, options and resource limits. Inspection reports effective settings and capabilities without contacting endpoints or running models. The desktop Pipelines screen saves and inspects the same definitions; Library processing selects their IDs.</p>

A supplied or generated text-only result without usable timing cannot be silently assigned invented intervals. Metadata capture precedes transforms under <a href="/docs/v1.1.0/ingestion/">ingestion</a>.</p>
<p>The pinned local Whisper adapter intersects a final predicted endpoint with decoded media only when its overrun is at most 250 milliseconds, and records the exact change in <code>whisper_end_intersected_decoded_media</code>. Community-1 frame intersections use the same maximum with their separate diagnostic. Larger excursions, reversed intervals and generic adapter results remain invalid. These adapter policies preserve the decoded source boundary; they do not establish prediction accuracy or add audio beyond that boundary.</p>
<h2 id="resumable-source-clock-windows">Resumable source-clock windows</h2>
<p>New processing requests for sources longer than 30 seconds automatically use bounded windows. An explicit <code>windows</code> object also enables them for short sources. Existing admitted work retains its frozen election. The same policy applies to newly configured import processing, CLI requests and desktop requests through the shared runtime.</p>
<p><code>windows.core_us</code> defaults to 30000000 (30 seconds) and accepts 1000000 through 300000000. <code>context_us</code> defaults to the smaller of 2000000 and half the core; explicit zero disables overlap. <code>concurrency</code> defaults to 1 and accepts a cap up to 4; the current executor runs one window at a time within that cap. Zero core or concurrency selects its default. At most 16384 windows and 64 selected track/channel lanes fit one plan. Larger jobs require a larger core or a narrower elected source range.</p>
<p>Optional <code>tracks</code> entries contain <code>stream_index</code>, optional <code>channel</code>, inclusive <code>start_sample</code> and exclusive <code>end_sample</code>. Sample indices use the original track's native sample rate, not microseconds or the 16 kHz inference rate. Omitted bounds cover the track. Omitted channel means downmix; distinct channels and streams remain independent lanes. Without <code>tracks</code> the existing selected audio stream/channel is used. Do not combine explicit tracks with <code>audio.stream_index</code> or <code>audio.channel</code>. A direct per-run <code>windows</code> object takes precedence over the saved pipeline and its window override. Advanced window/range controls are available through CLI JSON and saved definitions; the desktop uses their effective settings without dedicated range controls.</p>
<p>The versioned window-plan contract binds canonical source bytes/revision, current document, exact model and adapter identity, language/context, device policy and resource limits. Native sample counts and rational source origins determine contiguous cores and bounded overlap. Verified source chunks feed one continuous resampler per selected lane. Only the active window is materialized as mapped WAV; the runtime does not create a whole-recording PCM derivative or download the full source for each window. Planning verifies source bytes and counts samples before inference; this preparation still reads the source even when all inference checkpoints can be reused. See the generated <a href="/docs/v1.1.0/schema/">contract reference</a>.</p>
<p>Each completed window publishes verified output bytes and commits their digest, size, plan/window identity and owner generation to the catalog. Work inspection reports completed and total windows. Cancel or interruption preserves completed checkpoints; explicit retry verifies and reuses compatible outputs, then resumes incomplete windows. Source, range, model or semantic-setting changes require a new compatible plan. Corrupt or partial output cannot become a checkpoint. Publication and current-document acceptance use the existing fenced work and artifact journals. Portable backup includes active checkpoint bytes; accepted current results retire checkpoint transcript bytes through normal deferred cleanup. Hashes and compact stage/device observations remain provenance, while the catalog still owns one current Cueson document.</p>
<p>Recognition responses may supply <code>words</code> with integer <code>start_us</code>, <code>end_us</code> and <code>text</code> inside each segment. These are mapped-window-relative observations. Missing or unusable word timing retains segment evidence and an explicit boundary uncertainty diagnostic. Reconciliation uses both time and text to remove corroborated overlap observations, preserves genuine repetitions and conflicting alternatives, and records which windows produced each current cue. Source tracks are stitched separately. Diarizer labels remain window-local unless the existing speaker association workflow establishes a known identity; coincident labels do not prove the same voice. Cue/voice source provenance also governs downstream speaker selection, matching and training.</p>
<p>Local pyannote <code>batch_size</code> accepts 1 through 64 and defaults to 1 (omission or zero). A CUDA out-of-memory result with a larger elected batch permits one fresh attempt at batch 1. If that fails with a classified CUDA condition, the existing elected policy may try CPU once, under the original execution deadline. Model, route, source window and semantic settings remain fixed. Requested, attempted and actual devices plus the resource adjustment are recorded per window. CPU memory exhaustion returns an actionable <code>resource_exhausted</code> result; it does not loop or switch providers.</p>

<p>A pipeline mutation carries <code>expected_revision</code> and <code>pipeline</code>, whose fields are <code>id</code>, <code>name</code>, <code>preset</code> and <code>configuration</code>. Configuration contains <code>recognition</code>, <code>diarization</code>, optional <code>quality</code> and optional <code>windows</code>. Each supplied per-run override replaces that complete stage, quality policy or window election; it does not merge arbitrary option keys. Inspection input is optional and accepts <code>revision</code>, <code>overrides</code> and <code>context</code>.</p>

<h2 id="hosted-worker-contract">Hosted worker contract</h2>
<p>The <code>insonic-http</code> adapter uses contract version <code>1</code>. An operator configures the endpoint, remote model, declared transcription/diarization capabilities, supported hint budget and optional opaque credential ID. It sends one multipart POST containing a <code>request</code> JSON field and an <code>audio</code> field with the selected mapped WAV. The request identifies contract version, operation, model and effective options. The recognition response contains timed text segments; the diarization response contains voice turns. Both use integer mapped-audio-relative microseconds and an explicit <code>no_speech</code> result. The runtime validates bounds and projects results onto the original source clock before assembly.</p>
<p>An arbitrary provider API is not automatically compatible with this worker protocol. Provider-specific services can implement it through an adapter. Endpoint inspection validates configuration but reports reachability as not probed. Execution resolves only the elected credential and sends it as a Bearer authorization header. Redirects are refused; endpoint user information, query strings and fragments are rejected. Credentials require HTTPS, with an explicit loopback HTTP exception for locally hosted services. Errors return fixed categories without provider response bodies, credential values or endpoint details.</p>
<p>Local and hosted stages both use bounded audio, response and timeout settings. Omitted limits normalize to 128 MiB audio, 16 MiB response and 600000 milliseconds; explicit limits are validated before submission. A route or capability failure never chooses another provider or model. Only classified local CUDA failures permit the elected policy's bounded CPU recovery within the same deadline.</p>
<h2 id="local-processing-and-quality-diagnostics">Local processing and quality diagnostics</h2>
<p>Mapped audio records original source digest, selected stream/channels, sample format, tool identity and exact source-time mapping. The selected local recognizer and diarizer receive verified managed model files, not an ambient latest model name. Missing or invalid models, incompatible capabilities and unsupported device selection produce actionable failure. A local failure never chooses hosted routing. CPU recovery under the local device policy records its attempted devices and generated reason.</p>
<p>Local workers import engine packages lazily only for elected product processing or explicit maintainer qualification. Offline execution prevents ambient model retrieval. Literal argv, protected bounded input, separate bounded output, hidden Windows creation and supervised cancellation apply to every worker. Model files are materialized under confined relative names; temporary stage output is cleaned after success, failure and cancellation.</p>
<p>Automatic diarization diagnostics are enabled by default and describe speech coverage, overlap, short turns, boundary/timing consistency and empty output. The quality policy can set minimum speech coverage, maximum overlap fraction and a short-turn threshold, or disable these optional checks. They are separate from Cueson schema validity. A valid assignment document does not prove voice accuracy. Reused diarization quality is recomputed from current embedded millisecond assignments and the current source map; its provenance names that quantized current-document basis rather than implying a fresh acoustic engine run. No-speech and unusable timing remain explicit outcomes, and diagnostics do not create a manual review queue. Maintainer qualification records exact model/settings, resource use, recognized text and speaker/timing diagnostic method; it never injects reference subtitles as generated recognition output.</p>

<h2 id="required-checks-and-maintainer-evidence">Required checks and maintainer evidence</h2>
<p>No CI suite, native/backend qualification or required status check invokes transcription/diarization, initializes or loads their models, downloads model weights or requires engine results. The rule applies even to small or cached models. Deterministic tests supply stage results at the adapter boundary and may probe/extract committed real media and execute Cueson. Actual recognition/diarization quality testing requires the explicit opt-in maintainer path outside CI and merge requirements.</p>
<h2 id="current-evidence-extraction">Current evidence extraction</h2>
<p>Evidence extraction operates on accepted current Cue JSON through the shared durable-work runtime. The builtin cue-statement adapter preserves literal source ownership; an explicitly configured HTTP adapter can supply propositions with cue citations, polarity, modality and conditions. Acceptance validates current recording revision, document digest and cited local voices. Replacement invalidates that extraction. <a href="/docs/v1.1.0/graph/">Graph operations</a> document executable inputs, bounds and provenance. Required CI exercises deterministic supplied replies and never initializes models.</p>

<h2 id="local-signal-and-failure-outcomes">Local signal and failure outcomes</h2>
<p>Verified exact zero-signal audio yields an explicit no-speech result without invented recognition cues. Quiet nonzero audio is not discarded by an arbitrary amplitude threshold. Human, verbose, debug and JSON work inspection retain these causes without raw engine output. Failed attempts preserve the previous accepted document.</p>

<p>Repair freezes the source/document revisions and digests, speaker mappings, exact processing election, coverage basis, normalized scopes and window budgets. It never silently chooses a different provider or model. Only selected windows execute. A candidate must preserve unrelated cue semantics, pass native Cueson validation and strictly improve a measured defect without losing covered text or worsening another protected metric. A valid non-improving candidate returns <code>unchanged</code>. Source changes, speaker corrections, cancellation, invalid output and exhausted budgets leave the accepted transcript authoritative. A candidate crossing a declared scope boundary is retained as an unchanged decision rather than clipped without adequate timing evidence.</p>
<p>Acceptance replaces the current Cueson document in one catalog transaction and applies the ordinary speaker-mapping, evidence, dataset and graph invalidation rules. The receipt records scopes, consumed attempts and before/after metrics. Verified temporary checkpoints are retired after accepted or unchanged decisions; failed work retains compatible checkpoints for bounded retry. Replay uses the accepted receipt without rerunning inference. The CLI and shared runtime expose these advanced operations; the GUI currently has no dedicated coverage or repair controls.</p>
