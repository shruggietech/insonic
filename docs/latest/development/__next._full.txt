1e:T4b4d,<h1 id="development-workflow">Development workflow</h1>
<p>Optional worker profiles use complete platform wheel hashes and isolated CPython/uv acquisition. Deterministic CI checks exercise their contracts without inference; elected CPU runs validate actual libraries and models separately. The maintainer acoustic harness reads the same builtin model manifests as the product. See <a href="/docs/v1.0.1/processing-setup/">local processing setup</a>.</p>
<h2 id="tracking-and-scope">Tracking and scope</h2>
<p>GitHub Issues are the primary work intake, milestones define release outcomes and a GitHub Project provides status. Issues state concrete acceptance, affected versions for defects, dependencies and scope exclusions. The board tracks issues and pull requests without duplicating task text. Use statuses Backlog, Ready, In progress, In review and Done, with Slice, Release, Priority and Area fields.</p>
<p><a href="/docs/v1.0.1/roadmap/">Delivery outcomes</a> describe product dependencies. Numbered implementation plans and verification records live under <code>specs/</code>; public documentation describes system contracts and does not render those planning artifacts.</p>
<h2 id="spec-kit-slices">Spec Kit slices</h2>
<p>Spec Kit organizes bounded, observable work. Python 3.11 or newer supports its cross-platform maintainer helpers. The application runtime uses the language and dependency boundaries defined in <a href="/docs/v1.0.1/technology/">technology decisions</a>.</p>

<h2 id="building-the-workspace-runtime">Building the workspace runtime</h2>
<ol>
<li>Use Go 1.27.1, as pinned in <code>go.mod</code>, and Node 22 or newer for documentation.</li>
<li>Run <code>go test ./...</code> and <code>go vet ./...</code>.</li>
<li>Build the CLI with <code>go build -o build/insonic ./cmd/insonic</code> (use <code>build/insonic.exe</code> on Windows).</li>
<li>Run the built executable with <code>workspace init &lt;directory&gt; --json</code>.</li>
<li>Select it with <code>--workspace &lt;directory&gt; workspace show --json</code> or discover it by running inside that workspace.</li>
</ol>
<p>Workspace initialization validates the packaged JSON contract and cannot replace an existing workspace. Clients share a current-user local runtime; it starts on demand and exits after idle time. <code>jobs start &lt;milliseconds&gt;</code>, <code>jobs show &lt;job-id&gt;</code>, <code>jobs history &lt;job-id&gt;</code>, <code>jobs cancel &lt;job-id&gt;</code> and <code>jobs retry &lt;job-id&gt;</code> exercise a bounded durable qualification operation. Jobs and attempts survive owner restarts. Interrupted or expired attempts resume through fresh fenced claims; cancelled jobs remain cancelled until explicit retry. <code>doctor --json</code> reports the available catalog and configured storage/graph profiles without returning credential values or switching backends.</p>
<p>The desktop uses a statically bundled React/TypeScript client and packages local documentation. Run <code>npm ci --prefix desktop/frontend</code>, then its <code>check</code>, <code>test</code> and <code>build</code> scripts before native desktop qualification. Library, Jobs, Pipelines, Speakers, Terms, Models, Explore and Settings controls use the shared runtime operations. Native qualification pins exact dependencies, verifies artifact checksums and executes bounded platform/backend fixtures. Artifact availability on an architecture does not establish executed package support.</p>
<p>After native dependency preparation and matching documentation/frontend builds, <code>python scripts/package-desktop.py all --variant both</code> builds and qualifies CLI-only and GUI-with-CLI packages. <code>--variant cli</code> or <code>--variant desktop</code> selects one variant. Source-complete media companions retain verified source archives, build recipes, compiler identity and capability receipts. Portable artifact backups use the offline maintenance commands described in <a href="/docs/v1.0.1/storage/">storage</a>; they do not start processing workers. <a href="/docs/v1.0.1/releases/">Release tooling</a> binds the complete four-package matrix and documentation to one reviewed clean source revision.</p>
<p>For durable media/model work, <code>insonic work wait WORK_ID --timeout-ms 30000 --json</code> waits through runtime IPC in one client process. The default timeout is 30 seconds and the maximum is ten minutes. It returns the observed terminal state; failed, cancelled, interrupted or timed-out waits exit nonzero and retain the last observed state. A wait timeout does not cancel the job.</p>
<p>Managed artifact commands share this runtime: publish/show/verify/materialize/reconcile/abort/retire, retention reference admission/release, materialization lease renewal/release and expired cache pruning. Their exact usage, default bounds and recovery behavior are defined in <a href="/docs/v1.0.1/storage/">storage</a>. They operate on real bytes through filesystem/S3 adapters, including library import/metadata, downloaded models and current recording derivatives. Dedicated desktop storage controls remain pending, while the shared bridge accepts the versioned runtime operations.</p>
<p>Owner locks use the private per-user runtime directory and canonical workspace root, so read-only metadata and control-directory edits preserve one owner. A runtime admits up to 1,024 active qualification workers. Terminal history remains in the selected catalog and cannot consume active-worker capacity. Runtime shutdown records interruption rather than user cancellation. Five-second attempt leases renew every second; recovery claims only expired or explicitly interrupted authority, preserving prior attempts.</p>
<h2 id="automated-checks-and-user-observations">Automated checks and user observations</h2>
<p>Before merging, run checks relevant to changed behavior, dependency/artifact integrity and reproducible builds. Secret redaction, archive extraction, job attempt ownership and graph publication require meaningful tests. Reversible text changes need formatting and link checks.</p>
<p>Users ordinarily verify released behavior and report observations through issues. A report includes version, platform, expected/actual behavior and a minimal reproduction. Correlate symptoms before asserting a cause. A green unrelated unit suite does not resolve a reported field observation.</p>
<h2 id="ci-budget">CI budget</h2>
<p>Repository CI has parallel integrity, documentation, native-platform and alternative-backend jobs. Native checks run on Linux and Windows, including real dependency operations and the desktop bridge. Backend fixtures exercise PostgreSQL, S3-compatible storage and ArcadeDB. Foundation and documentation checks always run. A change classifier keeps stable platform check names while skipping expensive native work for prose-only changes. Runtime/catalog/schema changes run core and native acceptance plus PostgreSQL catalog fixtures; unknown paths and unavailable diffs receive full qualification. Declared Go, Wails and Ladybug binding pins must match qualification metadata. Package qualification compares each variant's notice inventory with its linked Go executable modules and rejects missing or mismatched upstream licenses. Documentation checks include KaTeX option handling and hidden headless rendering of public/offline diagrams through both themes. Each CI and release job has an eleven-minute timeout. Cache dependencies, cancel obsolete branch runs and consume committed assets and lockfiles. Network brand freshness checks are manually triggered.</p>
<p>Measure end-to-end turnaround. Keep the complete elected CI workflow within eleven minutes (660 seconds). When it approaches this budget, remove redundant work, tighten change scopes or parallelize independent checks. Native jobs build and qualify relocated desktop packages for their executed OS/architecture. CI retains inventories, checksums and receipts; public binary promotion belongs to release delivery. No CI suite, native/backend qualification or required check invokes transcription/diarization, initializes or loads their models, downloads model weights or requires engine results, including cached or small models. Deterministic stage results exercise orchestration and document/storage contracts; bounded real-media probing/extraction, preview encoding and exact Cueson operations are allowed.</p>
<h2 id="explicit-maintainer-engine-qualification">Explicit maintainer engine qualification</h2>
<p>Committed CC BY 3.0 speech audio and a short dialogue video are ordinary Git files under <code>tests/fixtures/media/</code>, with license/attribution, source/rendition/crop provenance, hashes, measured streams and separately declared reference expectations. Clean checkout and CI use these bytes without Git LFS or test-time media downloads. Supplied subtitles and constructed speaker turns qualify document/timing behavior, not model quality.</p>
<p>Actual recognition and diarization testing runs only through the explicit opt-in maintainer path. It is outside CI and merge requirements. Select installed local Python environments and registered exact managed models, record settings/device/thread/time/output bounds, and retain measured resource and quality diagnostics. No worker silently downloads weights or routes to another provider/device. A reference-text oracle cannot be supplied as alleged generated recognition output.</p>
<p><code>insonic processing tools CONFIGURATION.json</code> validates the registered <code>processing-tools</code> contract before publishing workspace configuration. Selected executables and the worker require absolute paths and lowercase SHA-256 identities; decoder configuration also requires its exact version. Positive duration, input/output, wall-time and thread limits are checked independently of inference. Omitted inference tools remain valid for supplied-subtitle assembly and export, and explicit readiness checks import libraries without loading models. Actual inference is qualified when its operation runs. CPU is the default; selected CUDA failure never silently switches devices.</p>
<p>Local inference, processing decoders and Cueson receive an explicit execution environment rather than the runtime's application/provider credentials. Preserve <code>PATH</code>, <code>SystemRoot</code>, <code>WINDIR</code>, <code>TEMP</code>, <code>TMP</code>, <code>TMPDIR</code>, <code>LANG</code> and <code>LC_ALL</code> with Windows case-insensitive selection. Preserve <code>LD_LIBRARY_PATH</code> on Linux, <code>CUDA_PATH</code> on Windows, and <code>CUDA_VISIBLE_DEVICES</code> on Linux/Windows. Inference workers receive explicit offline flags and a disposable private empty <code>HOME</code>/<code>USERPROFILE</code> for libraries that require home-directory discovery. The operator's home, application configuration and model-provider credentials are not inherited. Remove that private home after success, failure or cancellation.</p>
<p>Report recognition/timing agreement, speaker-count/coverage/overlap diagnostics and their reference basis separately from schema/document validity. Published subtitle display windows and editorial character labels are not sample-accurate voice activity or biometric identity truth. Distinguish measured engine behavior, deterministic regressions and unverified platforms in the qualification receipt.</p>
<p>Saved pipeline, speaker and terminology qualification uses deterministic local adapter results and bounded loopback hosted-worker fixtures. Protocol tests exercise actual HTTP request shape, mapping, credentials, redaction, redirects, response limits and cancellation without contacting external services. Required checks never call recognition or diarization models, download weights or use live provider inference. CLI and desktop bridge tests share the runtime contracts and explicit revision inputs.</p>
<h2 id="documentation-and-contract-governance">Documentation and contract governance</h2>
<p>Public documentation states the authoritative system behavior. Keep slice identifiers, task records and verification evidence in internal planning. Historical and version-change descriptions belong in the <a href="/docs/v1.0.1/changelog/">changelog</a>. The documentation index carries the concise implementation-status statement.</p>
<p>Use numbered steps for a procedure with one linear path. Use a diagram when branches, relationships, dependencies, feedback or retry paths explain the system more clearly. Keep Mermaid flowcharts top-down with <code>TB</code> or <code>TD</code> orientation.</p>
<p>The software, documentation and master JSON Schema share one release version. The <a href="/docs/v1.0.1/contracts/">JSON contracts</a> define machine-readable boundaries; the <a href="/docs/v1.0.1/schema/">logical catalog schema</a> defines relationships and integrity. Prefer backward and forward compatibility where practical. Explain breaking changes in the changelog and concise release highlights, including the migration or affected interface.</p>

<h2 id="github-setup-and-merging">GitHub setup and merging</h2>
<p>The maintainer bootstrap configures Issues, squash-only merges, automatic merged-branch deletion, labels, milestones and a Project. Branch protection requires the <code>foundation</code> and <code>docs</code> checks and resolved conversations. Activate protection after those checks exist.</p>
<p><code>npm run github:check</code> reads setup status. <code>npm run github:apply</code> applies prepared settings to an existing repository with repository-administration and organization-Project permissions. It does not create or push a repository. Repeated setup reuses tracked issues, milestones and the Project, preserving edits, existing values and archived work. Initial status setup applies only to a new empty Project. Missing required status options or established-item metadata are reported for completion. After a partial failure, resolve permissions, rerun and confirm settings and membership through API readback.</p>
<p>Squash merges follow green required checks and resolved review findings. Human PR approval, code-owner approval and last-push approval are not mandatory. The bootstrap preserves zero required approvals; automated analysis and focused checks remain part of development. Agents follow the owner's authorization for the merge itself.</p>
<p>See <a href="/docs/v1.0.1/references/contributing-md/">contribution guidance</a> and <a href="/docs/v1.0.1/releases/">release workflow</a>.</p>
<p>Windows native preparation installs its pinned archive decoder with <code>python -m pip install --target build/native/python zstandard==0.25.0</code>. The prepared graph loader uses checksum-pinned OpenSSL ABI-3 companions, and relocated packages include their exact DLLs and Apache 2.0 notice beside the executables. No ambient OpenSSL PATH is required.</p>
<h2 id="extracted-package-connected-qualification">Extracted-package connected qualification</h2>
<p>Both package variants include <code>companions/processing/processing-worker.py</code> in their verified inventory. An elected maintainer journey uses <code>python scripts/qualify-journey.py --package ARCHIVE --package-receipt RECEIPT --revision FULL_COMMIT --mode controlled|real --recognition-python EXECUTABLE --diarization-python EXECUTABLE --output RECEIPT</code>. Real mode additionally requires exact installed <code>--recognition-model</code> and <code>--diarization-model</code> snapshots. This qualification runs outside CI in owned disposable workspaces and a private home; it does not use an operator library.</p>
<p>Package selection verifies archive/inventory/source receipts, clean elected revision, current versions and platform, then extracts into a directory containing spaces. CLI, media tools, Cueson and the real worker resolve only inside that installation. Development CLI/tool overrides are rejected, and ambient native loaders, tool overrides and credentials are removed from child execution. Python environments and offline models remain explicit inputs. Controlled mode records its synthetic fixture worker separately from the installed real worker.</p>
<p>The connected journey covers generated current transcripts and source maps, speaker enrollment/profile selection, roster-constrained matching, native queries, self-contained backup, source withdrawal and exact current-authority recovery in an empty destination. Receipts distinguish package source identity from the maintainer harness and identify exact inputs. Successful connected operations establish execution and recovery for those fixtures; they do not establish independent biometric accuracy, attended GUI behavior or unexecuted platform inference.</p>
