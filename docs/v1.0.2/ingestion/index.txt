1d:Ta088,<h1 id="import-metadata-and-dates">Import, metadata and dates</h1>
<h2 id="a-definite-import-workflow">A definite import workflow</h2>
<p>Import accepts local audio/video, a batch manifest or an acquisition adapter's output. New admission stores canonical audio in the configured artifact store. Existing copied/reference media remains readable; new reference admission reports an explicit unsupported request. <code>--preset</code> selects a saved import preset by UUID or exact name, applying its destination, date options and optional saved pipeline before queueing. Missing, deleted, ambiguous or incompatible selections fail with a diagnostic; they never silently fall back. A configured batch runs without approving every file or stage.</p>
<p>Capture metadata from the original bytes as soon as a stable readable source is available, before transcoding, resampling, remuxing, stripping tags or producing a proxy. For remote sources, retain available acquisition metadata before download and extract embedded metadata from the downloaded original before transformation. A source that has already lost metadata cannot have those missing fields reconstructed as facts.</p>
<ol>
<li>Accept local files, a batch manifest or an acquired original.</li>
<li>Read stable original bytes and compute their identity.</li>
<li>Capture embedded metadata and stream facts.</li>
<li>Select and validate an explicit or embedded transcript, then prepare canonical audio.</li>
<li>Publish verified candidates and atomically commit the media, optional current document, observations and selected-date state.</li>
<li>Make the accepted library entry available and reconcile unused managed candidates.</li>
<li>Return durable work and per-item admission results, including the effective preset revision and queued processing job IDs. An elected pipeline creates one durable processing child after each accepted item; admission and processing retain separate completion states.</li>
</ol>
<p>The admission receipt binds original and canonical digests, byte sizes, track-clock maps, acquisition/import times, metadata report digests, extractor versions/options, probe results, effective date policy and selected artifact locations. Detect a source changing during copy or extraction and retry from stable bytes instead of joining a report to the wrong asset. Derived processing starts only after canonical admission and the capture attempt are recorded.</p>
<h2 id="saved-import-presets">Saved import presets</h2>
<p>Import presets are workspace records, separate from pipeline kinds (<code>local</code>, <code>connected</code>, <code>custom</code>). Create one before using <code>--preset</code>; there is no builtin import preset named <code>local</code>. The desktop Import presets screen creates IDs and uses the displayed revision for edits/deletion. CLI inputs use ordinary UUIDs; the example below supplies valid fresh IDs for a disposable workspace. Use your own UUIDs when those IDs already exist.</p>
<p>Save this as <code>preset-create.json</code>. The explicit filesystem destination is relative to the workspace control directory. Omitting <code>destination</code> uses the workspace storage profile; an S3 destination uses the same <a href="/docs/v1.0.2/storage/">storage profile contract</a> and opaque credential references.</p>

Explicit <code>false</code>, zero-valued stream indexes and empty pipeline IDs remain explicit choices. <code>--no-pipeline</code> clears an inherited processing election. Omitted options keep established runtime defaults; local timezone capture occurs after this merge. CSV uses the same option names, with <code>pipeline_id</code> value <code>none</code> to clear processing and a quoted JSON <code>destination</code> cell for an explicit profile. <code>--destination-profile storage-profile.json</code> accepts the same complete profile object as <code>destination</code>.</p>
<p>To elect processing, save a usable <a href="/docs/v1.0.2/pipelines/">pipeline</a>, then set its returned UUID as <code>options.pipeline_id</code>. Submission freezes the pipeline revision, effective stages, tools and model manifests. Missing compatible model bytes acquire through existing durable dependencies; missing pipelines, unavailable tools or credentials fail with readiness diagnostics before admission is queued. Supplied/current text bypasses recognition. Each accepted item queues one deterministic child, and retries reconcile that child instead of creating duplicates. Omit/clear the pipeline for intentional admission-only work. Snapshots retain presets and profile references; after transfer, inspect destination configuration and tool bindings before new work. Retained publications continue to resolve by their own profile revision. A refresh destination applies to newly published extractor reports and elected processing outputs; it does not move existing canonical audio.</p>
<h2 id="metadata-preservation">Metadata preservation</h2>
<p>EXIF is one supported metadata family; audio/video can also carry XMP, ID3, RIFF/BWF, QuickTime and other container tags. Capture all available families, container-level tags and per-stream facts, rather than requiring every file to contain EXIF. <a href="https://github.com/exiftool/exiftool/blob/master/README">ExifTool</a> is the default embedded-metadata extractor; <a href="https://ffmpeg.org/ffprobe.html">ffprobe</a> supplies complementary container, stream and codec facts. Release packages pin these tools and include their licensing notices.</p>
<p>Persist the current raw extractor report and separate typed normalized observations. A refresh replaces the current computed metadata and physically retires superseded reports after active materialization leases are released. Keep canonical audio and the current document source envelope; preserve owner-owned input files. Preserve tag group/path, duplicate instance, original value, units, precision and warnings. ExifTool JSON can suppress identical tag names unless instance-qualified groups are requested; the extraction contract must retain duplicates and structured values. <a href="https://github.com/exiftool/exiftool/blob/master/html/exiftool_pod.html">Official extraction documentation</a> describes these options. Unknown fields remain in captured reports when available. A retired original cannot supply fields omitted by an extractor; bounded capture reports its coverage rather than reconstructing missing facts. Report truncation and coverage explicitly.</p>
<p>For a readable legacy local reference, retain the extracted report and available metadata payload artifacts immediately even though media stays outside managed storage. Later source loss leaves those captured observations intact; it cannot guarantee recovery of an unparsed field that existed only in the missing original. State that availability limit, and use canonical managed admission for durable audio.</p>
<p>Capture states are <code>captured</code>, <code>no-embedded-metadata</code>, <code>partial</code>, <code>unsupported</code> and <code>failed</code>. Only a successful extraction with no embedded fields establishes <code>no-embedded-metadata</code>. Unsupported metadata extraction and errors retain the capture attempt alongside otherwise valid canonical audio and allow retry. They do not reject otherwise usable media or claim all metadata was captured. If a limit prevents complete extraction, keep the input item available with a visible partial state.</p>
<p>Store filename extension, acquisition-declared MIME type, byte-detected MIME type, extractor file type and probed container/codec separately. A normalized preferred MIME type records the resolver/version and disagreements. Do not overwrite observations with user edits. Metadata can be inaccurate before arrival; capture preserves what was received rather than certifying its truth. The details/CLI metadata view exposes raw and normalized observations with their source.</p>
<h2 id="origination-dates-and-timezones">Origination dates and timezones</h2>
<p>Origination means the recording's date/time, distinct from publication, retrieval, import, file modification and processing. Import permits <code>--originated-at</code> for a timestamp or <code>--originated-on</code> for a date without a known time. Use the captured local timezone by default for timestamps without an explicit zone. <code>--timezone</code> accepts <code>local</code>, <code>UTC</code>, an IANA identifier or an explicit numeric offset. Resolve <code>local</code> once for the import batch and save the actual zone/offset and timezone-database version; another machine must not reinterpret it later.</p>
<p>The platform timezone bridge resolves Windows/system zone identifiers to maintained IANA rules and retains its mapping/rules version. Use the offset for the entered recording time, not today's offset. An unavailable local-zone mapping reports an unresolved date and accepts an explicit zone; it does not stop media admission.</p>
<p>Timestamp literals accept up to nine fractional-second digits. Preserve the entered literal and resolved integer nanoseconds exactly, including through backup and restore; do not round-trip the integer through floating-point JSON values.</p>
<p>The default <code>owner-first</code> recording-date precedence is an explicit per-item owner value, a valid embedded recording timestamp with its own timezone, an embedded recording timestamp interpreted under the import timezone policy, then unknown. <code>--date-precedence</code> accepts <code>owner-first</code>, <code>embedded-first</code> or <code>filesystem-fallback</code>. Saved preset values are overridden by manifest defaults, then item fields, then explicit CLI flags. The receipt records the effective date policy and preset revision. Preserve every competing observation and the reason for selection. The configurable candidate mapping uses recording/creation tags with their documented meanings, never every tag containing a date. Filesystem modification time is available as a separately labelled observation and becomes a recording date only through an explicit policy or owner choice.</p>
<p>The <a href="https://www.iana.org/time-zones">IANA timezone database</a> supplies historical offset/daylight-saving rules. Store the entered wall-time literal, zone source, resolved offset, UTC instant when resolvable, precision, selection basis and assumption flags. A date-only input retains day precision rather than inventing a recording time. Approximate dates retain bounds; unknown dates stay in the undated timeline group. QuickTime integer date tags are particularly uncertain: <a href="https://github.com/exiftool/exiftool/blob/master/html/TagNames/QuickTime.html">ExifTool's upstream notes</a> describe cameras storing local values despite the format's UTC convention. Preserve the raw value and recorded interpretation policy rather than silently converting every such tag as UTC.</p>
<p>An unambiguous valid time resolves automatically. An explicit IANA zone and numeric offset must agree if both are supplied. For a repeated daylight-saving wall time, provide an offset or <code>--dst-fold earlier|later</code>. A nonexistent daylight-saving wall time needs a corrected value or explicit <code>--dst-gap shift-forward</code> policy. No silent DST adjustment is the default. Only the affected date observation remains unresolved; media admission and other batch items continue. Noninteractive results report <code>partial: true</code> and the required disambiguation in JSON; an unresolved date alone does not fail admission or make <code>work wait</code> return a failure exit. Missing metadata or an unknown date never triggers a compulsory review queue.</p>

<p>The CLI exposes import, inspection and date correction through these operations:</p>

Sources and transcript paths are resolved relative to the manifest location unless explicitly absolute. Do not put credentials in manifests; use configured credential IDs.</p>
<p>Manifest files and normalized durable import input are bounded to 8 MiB, with
at most 10,000 items. Path resolution and CSV-to-JSON expansion count toward the
normalized input budget; oversized input is rejected before enqueue. The local
request frame allows that input plus its envelope. Responses remain bounded to
1 MiB and use the result/report paging described below.</p>

<p>Per-item output reports media ID, byte identity, metadata capture state, date selection/assumptions and queued job IDs. Repeated admission reuses matching immutable bytes/reports while retaining explicit entry creation and metadata revisions. A date correction creates a new owner observation and selection revision and preserves the current raw report. Calendar controls consume this selected state. It does not change original tags, rewrite a transcript or rerun recognition.</p>
<p>Import and refresh return a durable <code>work_id</code>. A batch with failed admissions
has failed work state and retains
per-item results; <code>work retry WORK_ID</code> reconciles admitted entries and retries
the failed items. An admitted item with partial metadata or unresolved dates
remains usable and does not by itself fail the work. Unused canonical candidates from failed admissions are retired using the current-reference
fence, preserving shared or committed current artifacts.</p>
<p>An accepted metadata refresh succeeds while live report leases or current references defer physical retirement. Obsolete reports remain in durable pending cleanup; release or expiry permits the existing reconciliation process to retire them. Replaying accepted work reconciles its receipt without accepting another revision. Genuine storage or catalog failures remain reported separately from ordinary retention delays; inspect the current recording when recovering a failure after acceptance.</p>
<p>Inspect completion through
<code>work show</code>; large batches expose references through
<code>work results WORK_ID --after-ordinal 0 --limit 100</code>. Continue from the returned
<code>next_ordinal</code>. <code>media list</code>, <code>models list</code> and <code>work list</code> return summary pages
with <code>next_id</code>; pass that UUID with <code>--after</code> for the next page. Default and
maximum page size are 100. <code>media raw</code> returns current capture-bundle paths with
artifact leases rather than placing large reports in IPC frames. Oversized
normalized metadata also returns these reports with <code>metadata_inline: false</code>.
Release each lease after reading using <code>artifacts lease-release</code>.</p>
<p>HTTP acquisition has configurable byte and time budgets. The defaults are 64 GiB
and ten minutes per source. Set <code>--acquisition-max-bytes</code> and
<code>--acquisition-timeout-ms</code>, or the equivalent <code>acquisition_max_bytes</code> and
<code>acquisition_timeout_ms</code> batch/per-item manifest options, for larger recordings
or slower configured sources. Values must be positive; item options override
batch defaults. Declared and streamed responses exceeding the ceiling fail,
cancelled/timed-out downloads stop, and partial acquisition files are removed.
Local imports do not use this remote-download ceiling.</p>
<p>Credential-bearing acquisition uses HTTPS. Explicit <code>--local-http</code> (manifest
<code>local_http: true</code>) permits credential-bearing HTTP only for a loopback source;
it cannot permit plaintext remote authentication. Ordinary HTTP sources without
credentials remain supported. Authentication belongs in credential IDs, and
source URLs reject common query-authentication aliases before durable enqueue.</p>
<p>JSON date input can preserve approximate <code>originated_earliest</code> and
<code>originated_latest</code> bounds as exact <code>{iso, unix_ns}</code> UTC instants. Either bound
may be absent; two bounds must be ordered and their text and integer values must
agree. A bounded observation has range precision and no invented exact recording
instant. Per-item bounds replace batch bounds and cannot be combined with an
exact <code>originated_at</code> or <code>originated_on</code> value.</p>
<p>The CLI accepts <code>--originated-earliest</code> and <code>--originated-latest</code> RFC3339
timestamps for import, refresh and <code>set-origin</code>. It normalizes explicit offsets
to UTC and constructs exact integer nanoseconds without floating-point conversion.
Either flag may be omitted for an open bound. For example:</p>
<pre tabindex="0" aria-label="Code example"><code class="language-sh"><span class="hljs-title">insonic</span> media set-origin <span class="hljs-variable">MEDIA_ID</span> <span class="hljs-attr">--revision</span> <span class="hljs-variable">CURRENT_REVISION</span> <span class="hljs-attr">--originated-earliest</span> 2026-10-01T00:00:00Z <span class="hljs-attr">--originated-latest</span> 2026-10-07T23:59:59Z
</code></pre>
<p>Installed bundles discover their pinned extractors automatically. An explicit workspace override can configure exact extractor files using
<code>insonic media tools media-tools.json</code>. The rendered tools contract declares
absolute executable paths, SHA-256 values, emitted versions, delegated support
files and an explicit pinned interpreter when needed. The command starts or reuses the
shared runtime and saves the override for the next operation. Already running
operations retain their previous configuration. Missing or mismatched tools yield a visible partial/unsupported
capture and preserve usable media for retry. The controlled native qualification
uses ExifTool 13.59 and platform-specific ffprobe distribution binaries; installed
product bundles and their notices remain part of release assembly.</p>
<h2 id="low-interruption-processing">Low-interruption processing</h2>
<p>The CLI is the primary import contract; the GUI wraps the same flags, presets, validation and result states. Import screens show the timezone/default-date policy once for a batch, allow per-item overrides and offer a details view rather than a repeated modal sequence. Configured copies/uploads, extraction, processing, supported speaker attribution and elected training proceed through durable jobs. New external routing or a meaningful destructive choice requires an explicit configuration/action; previously selected routing does not need repeated confirmation.</p>
<p>Capture and dates belong to admission, timed audio belongs to processing, and speaker associations expose the library-wide corpus. <a href="/docs/v1.0.2/voice-models/">Speaker models</a> reuse this evidence when the user elects training. The <a href="/docs/v1.0.2/schema/">catalog schema</a> preserves observations and model lineage independently of the selected storage/database adapters. <a href="/docs/v1.0.2/contracts/">JSON contracts</a> define the import manifest and metadata payloads.</p>

<p>Standalone transcript items use <code>record</code> plus <code>transcript</code>, creating no second media entry. An exact title must be unambiguous. A current transcript causes a successful skip by default; <code>--replace-transcript</code> elects replacement. Invalid explicit replacement leaves current state unchanged and never falls back to embedded text or recognition. Converting a managed legacy sidecar retires that redundant managed publication after current acceptance and lease reconciliation.</p>
<p>Exact packaged Cueson 1.0.0 and 1.1.0 documents validate under their original schemas, then undergo a lossless identity upgrade to 1.2.0. Current 1.2.0 documents validate directly. Unknown versions report the supported versions; input schema URLs are never fetched. Admission preserves native/source payloads, exact integers, cues and supplied assignments; JSON whitespace may be compacted by catalog serialization.</p>
<p><code>--attribution auto</code> preserves any complete or partial assignments. Only a document with zero assignments derives recording-scoped untimed participation from structured native/heuristic speaker observations. <code>native</code> restricts derivation to native observations, and <code>off</code> preserves without deriving assignments. <code>diarize</code> requires <code>--diarization-model-id</code>, explicitly runs configured diarization and bypasses recognition for supplied text. Labels alone never create timed acoustic evidence or a known-person identity.</p>
<p><code>--diarization-model-id</code> and JSON/CSV <code>diarization_model_id</code> accept the shared
<a href="/docs/v1.0.2/models/">model reference grammar</a>: exact base IDs, <code>base:UUID</code>, aliases or
<code>source:NAME/SELECTOR</code>. Batch defaults apply unless an item overrides its
reference. Submission resolves each selected reference once, validates the
diarization adapter and freezes its complete manifest digest. Missing files
acquire through shared durable dependencies before import diarization; partial
batch retry retains that election after alias or source changes. Job inspection
shows the selected models and acquisition IDs. Supplied text is preserved and
recognition stays bypassed.</p>
<p>Media and transcript HTTP acquisition have separate credential IDs and budgets. Set <code>--transcript-credential-id</code>, <code>--transcript-max-bytes</code> (default and maximum 16 MiB), and <code>--transcript-timeout-ms</code> (default 120000, maximum 600000). Transcript bytes determine format independently of MIME and filename; HTML error bodies, incomplete downloads and invalid documents fail. <code>--transcript-format cueson|srt|vtt|ass|ssa</code> is an explicit hint validated by the selected parser. JSON/CSV item fields override batch defaults using the same shared contract. Advanced acquisition adapters are available through manifests/runtime input.</p>
<p>All embedded subtitle candidates remain inspectable in captured source-stream facts. An explicit transcript wins and reports unused embedded alternatives. Otherwise explicit index/language filters apply, then default disposition, non-forced disposition and stream order choose one supported text track. Alternatives are never concatenated. Image-only subtitles report an OCR requirement; burned-in captions require a separately elected OCR capability. Neither route silently runs an engine.</p>
<p>Standalone target selectors resolve to a recording ID and observed source/document revisions when queued. A delayed stale replacement fails instead of overwriting a later edit. Advanced manifest items can supply <code>expected_revision</code> and <code>expected_recording_revision</code> explicitly. Resubmit a new request to elect a changed target; accepted work retries reconcile their original receipts.</p>
<h2 id="replacement-and-initial-speaker-context">Replacement and initial speaker context</h2>
<p><code>media import SOURCE --record ID</code> targets existing audio and skips without candidate access unless <code>--replace-audio</code> is elected. Transcript and declared-roster policies follow <a href="/docs/v1.0.2/media/#explicit-audio-replacement">audio replacement</a>. Repeated <code>--known-speaker</code> references declare initial context on a new entry. A duplicate existing source keeps its accepted roster; use roster edits for that recording.</p>
<p>JSON items use <code>kind: &quot;media&quot;</code> for targeted audio and <code>kind: &quot;transcript&quot;</code> for the standalone <code>record</code> plus <code>source</code> transcript alias. Options <code>replace_audio</code>, <code>existing_transcript</code>, <code>transcript_applies</code>, <code>existing_roster</code> and <code>known_speakers</code> share batch/default and per-item precedence. Omitted <code>known_speakers</code> leaves the roster undeclared; <code>[]</code> declares empty. CSV accepts the same columns, with a JSON string array in each <code>known_speakers</code> cell. Observed <code>expected_revision</code>, <code>expected_recording_revision</code> and <code>expected_roster_revision</code> reject stale elected targets. Runtime work freezes resolved speaker IDs and target revisions before acquisition.</p>
