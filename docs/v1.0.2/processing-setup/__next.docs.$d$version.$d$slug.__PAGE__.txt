32:T47f1,<h1 id="local-processing-setup">Local processing setup</h1>
<p>Local recognition and diarization are optional. The CLI and desktop share the same worker setup, model acquisition and readiness operations. Ordinary imports and supplied subtitles do not require these engines. Settings provides local setup controls; the first-run wizard is a separate capability.</p>
<h2 id="prepare-an-environment">Prepare an environment</h2>
<p>Use the complete installed package, including its verified Cueson, FFmpeg and processing worker companions. In desktop Settings, select a role, preview its environment, then prepare it. The preview names its download size, temporary-space budget and destination. Setup runs as durable work visible in Jobs.</p>
<p>The managed CPU profiles use CPython 3.12.15 and uv 0.13.0, with complete platform-specific wheel hashes. Recognition uses faster-whisper 1.2.1 and CTranslate2 4.8.2. Diarization uses pyannote.audio 4.0.7 and CPU PyTorch 2.14.0, TorchAudio 2.11.0 and TorchCodec 0.17.0. Linux x86-64 requires glibc 2.28 or newer. These optional downloads are separate from package installation. They never install into global Python, modify PATH or replace an accepted environment in place.</p>

<p>The catalog contains exact runtime archives, wheels, source URLs and hashes. Runtime and installer archives are copied into the private owned attempt while hashing, and extraction uses only those verified snapshots. All required wheel bytes are verified before an offline, hash-locked installation. An unchanged accepted managed environment is verified and reused.</p>
<p>For the CLI:</p>
<ol>
<li>Inspect the available profiles with <code>insonic --workspace LIBRARY workers catalog --json</code>.</li>
<li>Save <code>environment-plan.json</code> with the following input.</li>
<li>Run <code>insonic --workspace LIBRARY workers plan --input environment-plan.json --json</code>. Check the returned prerequisite, destination, space and effect fields.</li>
<li>Copy the returned <code>result.election</code> object into <code>environment-setup.json</code>. It includes the automatically computed <code>profile_digest</code> and observed <code>expected_revision</code>.</li>
<li>Run <code>insonic --workspace LIBRARY workers setup --input environment-setup.json --json</code>.</li>
<li>Use its returned <code>result.work_id</code> with <code>insonic --workspace LIBRARY work wait WORK_UUID --timeout-ms 30000 --json</code>. Repeat the wait if still running. Inspect or cancel through <code>work show</code> or <code>work cancel</code>; retry failed/interrupted work through <code>work retry</code>.</li>
<li>Repeat the plan and setup with <code>diarization</code> if needed. A settings conflict requires a fresh plan; replay with the original request ID returns the original accepted work.</li>
</ol>

<p>Environments and their receipts live in the chosen library control directory. Cancellation removes the fresh failed preparation attempt; verified partial acquisition bytes remain available for retry. Successful setup publishes only the selected role after verification and a compare-and-swap settings check. Already accepted environments are retained for frozen work. Processing checks their interpreter, runtime, standard-library and dependency bytes before engine invocation.</p>
<h2 id="reuse-or-prepare-offline">Reuse or prepare offline</h2>
<p>Select an existing absolute interpreter path with <code>mode: &quot;reuse&quot;</code> and <code>python_path</code>. Inspection imports only the selected libraries, reports their versions and devices, and loads no model. Setup records and verifies their byte identities without installing into that environment. Its receipt/probe space budget is 32 MiB, rather than the managed profile installation minimum. Changes to these dependencies require a new explicit setup election.</p>
<p>For fully offline managed setup, add <code>offline_assets</code> with an absolute directory containing every declared archive and wheel under its exact catalog filename. Missing or damaged files fail locally. The installer uses only these files; it does not resolve alternate versions or fetch missing dependencies. Offline model reuse is separate.</p>
<p>An offline plan reports <code>download_bytes: 0</code>. <code>profile_download_bytes</code> retains the nominal complete profile size. <code>local_assets</code> reports required and verified expected byte totals, plus <code>missing_bytes</code> for missing or unusable declared files. It checks only the elected runtime, installer and wheels. Each failure identifies a logical filename, fixed role and verification reason with corrective advice; unrelated files do not contribute to these totals. An already verified accepted environment needs no new asset inspection or transfer.</p>
<p>Worker and model file errors distinguish missing, unreadable, nonregular, wrong-size and wrong-hash assets. The optional <code>error.asset</code> contains only a generated role and bounded slash-relative logical name. The same reason and correction survive JSON responses, human output and durable work inspection. These errors exclude owner paths, resolved credentials and raw tool output.</p>
<p>Existing explicit processing-tools configurations remain supported under Advanced. Accepted work freezes its interpreter, worker and environment receipt. Package-derived companion defaults are resolved from the current complete installation for future work, preserving relocation; accepted work keeps its original bytes.</p>
<h2 id="diagnose-worker-inspection">Diagnose worker inspection</h2>
<p>Run <code>insonic --workspace LIBRARY workers inspect --input inspection.json --json</code> with <code>{&quot;role&quot;:&quot;recognition&quot;}</code> or <code>{&quot;role&quot;:&quot;diarization&quot;}</code>. Omit <code>python_path</code> to inspect the configured interpreter. Inspection imports the selected engine and checks CPU/CUDA prerequisites without loading a model. Setup additionally inventories and hashes the environment before publishing its receipt.</p>
<p>The optional <code>probe</code> reports a fixed <code>mode</code>, <code>stage</code>, <code>reason</code>, native <code>elapsed_ms</code> and effective <code>budget_ms</code>. Its optional <code>child</code> contains an ordered <code>checkpoints</code> list and bounded file/hash counts. Native elapsed time begins before interpreter hashing. Child elapsed time begins inside the isolated interpreter; these clocks have different origins and must not be subtracted or added as stage durations. Observations are cumulative checkpoints, rather than independent phase durations. A failed or stopped interpreter may leave its last completed checkpoint; it does not prove later stages ran.</p>

<p>The standalone probe retains its sixty-second maximum and inherits any earlier caller deadline. Readiness shares one sixty-second allowance across its prerequisites. It retains already observed role facts and labels unattempted or interrupted prerequisites <code>unknown</code>; an exhausted allowance does not assert an import failure or changed dependency bytes. Hash verification also distinguishes an interrupted check from an actual checksum mismatch. Disconnecting an ephemeral inspection cancels its owned child. Durable setup retains its work identity and ordinary work cancellation behavior.</p>
<p>Human CLI output and desktop setup show the same bounded summary. Failed setup retains <code>worker_probe</code> facts in the durable work result and removes its fresh failed environment without publishing settings. Diagnostics exclude raw exceptions, tool output and host paths. Existing receipts without optional probe facts remain valid after their original byte and compatibility checks. Neither a successful diagnostic nor a warm import replaces receipt hashing, model verification or actual processing acceptance.</p>
<h2 id="acquire-exact-model-bundles">Acquire exact model bundles</h2>
<p>The product provides Whisper Tiny (MIT, 78,203,619 bytes) and Community-1 (CC BY 4.0, 32,821,421 bytes). Each choice has an immutable upstream revision and a complete named-file manifest. Inspect <code>insonic --workspace LIBRARY models defaults --json</code> for identities, license, model card and current state.</p>
<p>Community-1 segmentation frames with no overlap against decoded audio are discarded and diagnosed as padding-only predictions. Overlapping boundary extensions retain the 250 ms limit and are intersected with the real source interval with diagnostics. Generic adapter turns remain strictly bounded by decoded audio. Accepted cues never gain source time or samples from model padding.</p>
<ol>
<li>Save <code>model-preview.json</code> using the input below, selecting <code>whisper-tiny</code> or <code>community-1</code>.</li>
<li>Run <code>insonic --workspace LIBRARY models prepare --input model-preview.json --json</code>. Inspect verified reuse, download bytes, scratch space and the elected storage profile. Filesystem capacity is observed when available. Colocated scratch and artifact storage use a combined peak budget, including download and staging copies; unknown volume relationships are conservatively treated as shared. S3 capacity remains unknown.</li>
<li>Add <code>&quot;acquire&quot;: true</code> to that input and run the same command. Follow the returned <code>acquisition_work_id</code> through normal work commands or Jobs.</li>
<li>Confirm complete availability using <code>models inspect MODEL_UUID --json</code> and <code>models verify MODEL_UUID --json</code> before selecting it in a pipeline.</li>
</ol>
<pre tabindex="0" aria-label="Code example"><code class="language-json"><span class="hljs-punctuation">{</span><span class="hljs-attr">&quot;choice&quot;</span><span class="hljs-punctuation">:</span><span class="hljs-string">&quot;whisper-tiny&quot;</span><span class="hljs-punctuation">}</span>
</code></pre>
<p>An absolute <code>local_directory</code> reuses a complete existing snapshot after checking every declared role, size and SHA-256. It is published through the normal artifact service; source files remain unchanged. Omit <code>destination_profile_id</code> to elect the configured storage, or supply a saved storage profile UUID. Filesystem and S3 destinations use the same acquisition contract. A shared acquisition preserves its first destination and local/download route, and subsequent previews expose that frozen route.</p>
<p>Community-1 downloads require the upstream model access terms and a protected Hugging Face read token. Desktop Settings can register a token through native protected input and generate its opaque credential reference. CLI users register it through the documented <a href="/docs/v1.0.2/secrets/">credential commands</a>, then supply only <code>credential_id</code> to model preparation. Replace the same protected secret to rotate its token. Omitting the reference when preparing an existing choice retains its previously elected reference. A new gated download without the required protected reference is rejected before enqueueing; previews and local verified reuse need no download token. A supplied reference does not prove upstream authentication or model access. Credential values never enter manifests, work payloads or command arguments.</p>
<p>Preparation previews distinguish <code>credential_state</code>: <code>missing</code>, <code>locked</code>, <code>rejected</code>, <code>unavailable</code>, locally resolvable <code>available</code>, or <code>not_required</code>. An indexed reference alone does not establish readiness. The preview resolves required protected references locally and immediately clears the returned bytes; it sends no authentication request. <code>access_ready</code> describes this local prerequisite, while <code>upstream_authorization: &quot;not_checked&quot;</code> keeps upstream access separate. Complete verified installed or local reuse requires no download credential.</p>
<p>A failed local credential-status check reports <code>unavailable</code> without asserting that the reference is missing. Acquisition without its required locally resolvable credential returns <code>unavailable</code> with the generated reason <code>model_access_required</code>, before work is enqueued.</p>
<p>Pinned Hugging Face resolve requests may follow a bounded set of official model CDN redirects. Cross-origin requests strip credentials and cookies; signed CDN URLs are transient. All model bytes still require declared sizes and hashes. Custom sources retain their original same-origin transport policy.</p>
<h2 id="inspect-task-readiness-and-select-a-pipeline">Inspect task readiness and select a pipeline</h2>
<p><code>insonic --workspace LIBRARY processing readiness --json</code> reports five independent tasks: import, existing subtitles, transcription, diarization and training. Each includes actual prerequisites, observed availability, identities and corrective actions. <code>doctor</code> and <code>pipelines inspect</code> expose the same facts. Add <code>--input FILE</code> to inspect a specific <code>pipeline_id</code>, <code>pipeline_revision</code> and optional <code>dataset_id</code>.</p>
<p>Readiness verifies tools, environment imports, model bytes, selected storage and the requested device. It establishes prerequisites, rather than successful acoustic inference. Local custom trainer readiness checks the elected executable and support-file hashes without invoking the trainer. <code>file_verified</code> proves those prerequisites, without claiming protocol compatibility or model quality. Hosted routes remain <code>configured_not_probed</code>; a task with only unprobed prerequisites reports <code>unknown</code>, while an observed missing prerequisite reports <code>needs_attention</code>. Training additionally requires an elected current nonempty dataset. Pipeline usability combines the elected tasks, so a training-only definition does not require unelected recognition or diarization environments. The pyannote-profile adapter enrolls speaker embeddings; it does not retrain Community-1.</p>
<p>Desktop Settings can save a Local CPU pipeline with the exact builtin model IDs. Select it in Library when processing media, or inspect/edit it in Pipelines. Pipeline saving does not download weights or begin inference. Existing CLI <a href="/docs/v1.0.2/pipelines/">pipeline definitions</a> provide the same selection.</p>
<p>CPU and CUDA are explicit device choices. Managed profiles provide CPU dependencies. An existing CUDA environment must pass the selected engine/library probe; recognition also checks required cuBLAS 12 and cuDNN 9 libraries. Hardware count alone never establishes CUDA readiness. A failing CUDA job retains its original device, with a correction to verify compatible dependencies or explicitly elect CPU for future work. There is no automatic device fallback.</p>
<p>Pyannote receives an FFmpeg-decoded waveform tensor through the packaged worker. This path does not require TorchCodec shared-FFmpeg decoding. Recognition/diarization runtime success, CPU qualification, GPU execution and acoustic accuracy remain separate evidence.</p>
<h2 id="portable-restore">Portable restore</h2>
<p>Worker environments are host resources. A portable backup excludes their preparation paths and local model snapshot routes while retaining completed history and verified model artifacts. Prepare or reuse compatible destination environments before resuming restored processing; their verified receipts bind alongside destination interpreter/companion tools, while models, stage settings and devices remain frozen. Missing local acquisition inputs require an explicit new model preparation election. That recovery creates one shared successor work record and leaves the originating history intact.</p>
