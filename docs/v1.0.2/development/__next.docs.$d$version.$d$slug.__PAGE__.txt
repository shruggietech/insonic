32:Tb710,<h1 id="development-workflow">Development workflow</h1>
<p>Optional worker profiles use complete platform wheel hashes and isolated CPython/uv acquisition. Deterministic CI checks exercise their contracts without inference; elected CPU runs validate actual libraries and models separately. The maintainer acoustic harness reads the same builtin model manifests as the product. See <a href="/docs/v1.0.2/processing-setup/">local processing setup</a>.</p>
<h2 id="tracking-and-scope">Tracking and scope</h2>
<p>GitHub Issues are the primary work intake, milestones define release outcomes and a GitHub Project provides status. Issues state concrete acceptance, affected versions for defects, dependencies and scope exclusions. The board tracks issues and pull requests without duplicating task text. Use statuses Backlog, Ready, In progress, In review and Done, with Slice, Release, Priority and Area fields.</p>
<p><a href="/docs/v1.0.2/roadmap/">Delivery outcomes</a> describe product dependencies. Numbered implementation plans and verification records live under <code>specs/</code>; public documentation describes system contracts and does not render those planning artifacts.</p>
<h2 id="spec-kit-slices">Spec Kit slices</h2>

<h2 id="building-the-workspace-runtime">Building the workspace runtime</h2>
<ol>
<li>Use Go 1.27.1, as pinned in <code>go.mod</code>, and Node 22 or newer for documentation.</li>
<li>Run <code>go test ./...</code> and <code>go vet ./...</code>.</li>
<li>Build the CLI with <code>go build -o build/insonic ./cmd/insonic</code> (use <code>build/insonic.exe</code> on Windows).</li>
<li>Run the built executable with <code>workspace init &lt;directory&gt; --json</code>.</li>
<li>Select it with <code>--workspace &lt;directory&gt; workspace show --json</code> or discover it by running inside that workspace.</li>
</ol>
<p>Workspace initialization validates the packaged JSON contract and cannot replace an existing workspace. Clients share a current-user local runtime; it starts on demand and exits after idle time. <code>jobs start &lt;milliseconds&gt;</code>, <code>jobs show &lt;job-id&gt;</code>, <code>jobs history &lt;job-id&gt;</code>, <code>jobs cancel &lt;job-id&gt;</code> and <code>jobs retry &lt;job-id&gt;</code> exercise a bounded durable qualification operation. Jobs and attempts survive owner restarts. Interrupted or expired attempts resume through fresh fenced claims; cancelled jobs remain cancelled until explicit retry. <code>doctor --json</code> reports the available catalog and configured storage/graph profiles without returning credential values or switching backends.</p>
<p>The desktop uses a statically bundled React/TypeScript client and packages local documentation. Run <code>npm ci --prefix desktop/frontend</code>, then its <code>check</code>, <code>test</code> and <code>build</code> scripts before native desktop qualification. Library, Jobs, Pipelines, Speakers, Terms, Models, Explore and Settings controls use the shared runtime operations. Native qualification pins exact dependencies, verifies artifact checksums and executes bounded platform/backend fixtures. Artifact availability on an architecture does not establish executed package support.</p>
<p>After native dependency preparation and matching documentation/frontend builds, <code>python scripts/package-desktop.py all --variant both</code> builds and qualifies CLI-only and GUI-with-CLI packages. <code>--variant cli</code> or <code>--variant desktop</code> selects one variant. Source-complete media companions retain verified source archives, build recipes, compiler identity and capability receipts. Portable artifact backups use the offline maintenance commands described in <a href="/docs/v1.0.2/storage/">storage</a>; they do not start processing workers. <a href="/docs/v1.0.2/releases/">Release tooling</a> binds the complete four-package matrix and documentation to one reviewed clean source revision.</p>
<p>Native Windows build tooling gives CLI and desktop executables a process-local UTF-8 manifest so LadybugDB can open the selected non-Latin library path. Independent current-source package verification requires that manifest. Windows packages also give the pinned ExifTool launcher a process-local UTF-8 manifest so it can find its Perl runtime from non-Latin installation directories. Packaging preserves the original launcher and portable transformation recipes in corresponding sources, records original and transformed unsigned hashes, then signs and inventories the result. Archive verification reproduces those bytes independently; verified Authenticode signing permits only its declared signature envelope. The native dependency cache and system locale remain unchanged.</p>
<p>For durable media/model work, <code>insonic work wait WORK_ID --timeout-ms 30000 --json</code> waits through runtime IPC in one client process. The default timeout is 30 seconds and the maximum is ten minutes. It returns the observed terminal state; failed, cancelled, interrupted or timed-out waits exit nonzero and retain the last observed state. A wait timeout does not cancel the job.</p>
<p>Managed artifact commands share this runtime: publish/show/verify/materialize/reconcile/abort/retire, retention reference admission/release, materialization lease renewal/release and expired cache pruning. Their exact usage, default bounds and recovery behavior are defined in <a href="/docs/v1.0.2/storage/">storage</a>. They operate on real bytes through filesystem/S3 adapters, including library import/metadata, downloaded models and current recording derivatives. Dedicated desktop storage controls remain pending, while the shared bridge accepts the versioned runtime operations.</p>
<p>Owner locks use the private per-user runtime directory and canonical workspace root, so read-only metadata and control-directory edits preserve one owner. A runtime admits up to 1,024 active qualification workers. Terminal history remains in the selected catalog and cannot consume active-worker capacity. Runtime shutdown records interruption rather than user cancellation. Five-second attempt leases renew every second; recovery claims only expired or explicitly interrupted authority, preserving prior attempts.</p>
<h2 id="automated-checks-and-user-observations">Automated checks and user observations</h2>
<p>Before merging, run checks relevant to changed behavior, dependency/artifact integrity and reproducible builds. Secret redaction, archive extraction, job attempt ownership and graph publication require meaningful tests. Reversible text changes need formatting and link checks.</p>
<p>Users ordinarily verify released behavior and report observations through issues. A report includes version, platform, expected/actual behavior and a minimal reproduction. Correlate symptoms before asserting a cause. A green unrelated unit suite does not resolve a reported field observation.</p>
<h2 id="ci-budget">CI budget</h2>
<p>Repository CI has parallel integrity, documentation, native-platform and alternative-backend jobs. Native calls retain owned resources until their callbacks and reentrant native frames unwind. Its local lifetime regression uses an unshown message-only window, while actual browser qualification runs on disposable CI. Package qualification compares each variant's notice inventory with its linked Go executable modules and rejects missing or mismatched licenses and patch notices. Documentation checks include KaTeX option handling and hidden headless rendering of public/offline diagrams through both themes. CI, native, package, release, site and diagnostic qualification jobs allow sixty-five minutes; their cancellation watchdogs include cleanup/evidence headroom and are separate from aggregate qualification acceptance. Dependency/source preparation jobs allow sixty minutes. Administrative issue classification retains its independent two-minute limit. Cache dependencies, cancel obsolete branch runs and consume committed assets and lockfiles. Network brand freshness checks are manually triggered.</p>
<p>CI documentation and parallel package-input npm installs retain advisory auditing with expanded request allowances and at most two retries, bounded inside the enclosing preparation operation. Lockfile integrity, native/package acceptance and the qualification clock remain mandatory.</p>
<p>Measure dependency prerequisite preparation, qualification and combined elapsed turnaround separately. Exact cache verification or the cold source pipeline, plus elected Windows Go dependency preparation, must finish at an explicit readiness boundary before elected qualification starts, including foundation and documentation checks. Qualification targets thirty minutes (1,800 seconds) and has a sixty-minute (3,600-second) hard limit; exceeding the target through the hard limit is advisory and does not block otherwise valid acceptance or merge. Functional, integrity, provenance and elected required checks remain mandatory regardless of elapsed time. Queue time within each phase is included. First-attempt preparation and combined totals include the initial request-to-attempt queue interval, which is also reported separately. Its creation timestamp comes from the identity-verified workflow record; attempt-record creation is retained separately because it can follow attempt start. Reruns use their own attempt start. Acceptance receipts expose the effective target, hard limit and target overrun. The provisional aggregate reserves sixty seconds for finalization against the hard limit and rejects work whose elapsed time plus reserve exceeds 3,600 seconds. Final terminal job timestamps and the conservative workflow metadata envelope remain authoritative, including post-job cleanup; a provisional aggregate receipt is not final timing evidence. Target overruns may inform later proportional optimization; they are not a functional failure or an additional merge gate. <h2 id="explicit-maintainer-engine-qualification">Explicit maintainer engine qualification</h2>
<p>Committed CC BY 3.0 speech audio and a short dialogue video are ordinary Git files under <code>tests/fixtures/media/</code>, with license/attribution, source/rendition/crop provenance, hashes, measured streams and separately declared reference expectations. Clean checkout and CI use these bytes without Git LFS or test-time media downloads. Supplied subtitles and constructed speaker turns qualify document/timing behavior, not model quality.</p>
<p>Actual recognition and diarization testing runs only through the explicit opt-in maintainer path. It is outside CI and merge requirements. Select installed local Python environments and registered exact managed models, record settings/device/thread/time/output bounds, and retain measured resource and quality diagnostics. No worker silently downloads weights or routes to another provider/device. A reference-text oracle cannot be supplied as alleged generated recognition output.</p>
<p><code>insonic processing tools CONFIGURATION.json</code> validates the registered <code>processing-tools</code> contract before publishing workspace configuration. Selected executables and the worker require absolute paths and lowercase SHA-256 identities; decoder configuration also requires its exact version.
