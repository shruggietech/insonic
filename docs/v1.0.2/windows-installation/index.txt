20:T6e43,<h1 id="windows-installation-updates-and-removal">Windows installation, updates and removal</h1>
<p>Use the official release's Windows x86-64 setup EXE for installation and upgrades. It contains the exact raw MSI and coordinates local recovery. The MSI offers Desktop application, CLI or both; both are selected by default. The ZIP packages remain available for portable copying. amd64 means x86-64, including compatible Intel and AMD processors. The <a href="/docs/v1.0.2/index/">version index</a> states whether official downloads are available.</p>
<p>The Windows setup EXE, raw MSI and application are initially unsigned, with no verified publisher signature. A checksum identifies matching bytes; it does not add a signature or establish Windows reputation. Download, application reputation, permission approval, license acceptance and missing dependencies are separate checks.</p>
<h2 id="install-normally">Install normally</h2>
<ol>
<li>Open the <a href="https://github.com/shruggietech/insonic/releases">official releases</a>, choose the exact version and download its recommended <code>insonic_VERSION_windows_amd64_setup.exe</code>. Replace VERSION with that release's version. Keep its <code>SHA256SUMS</code> and <code>release-manifest.json</code> links for identity checks. If a warning appears, follow the matching branch below.</li>
<li>Install the <a href="#prerequisites">applicable prerequisites</a>, then open the downloaded setup EXE. Its native MSI pages install for the current user; it does not install for all accounts, acquire prerequisites over the network or add directories to PATH.</li>
<li>Read the actual Apache License 2.0 and select <strong>I accept the Apache License 2.0</strong>, which starts unchecked. Acceptance is required to continue.</li>
<li>Choose Desktop application, CLI or both. Desktop-only retains the shared runtime and command executable required by the application, while omitting exposed CLI launch integrations. CLI-only omits the desktop application and its WebView2 requirement. At least one client is required.</li>
<li>Keep the per-user program location under <code>%LOCALAPPDATA%\Programs\insonic</code>, or browse to a suitable writable program directory. Keep libraries, recordings, models and settings outside it. Spaces and non-ASCII names are supported. No user data is stored in installer-owned program files. An explicitly chosen directory is retained when saved installation metadata is read back.</li>
<li>Choose the optional desktop icon and Start menu integrations. The Start menu folder is <strong>insonic</strong>; the application shortcut is <strong>insonic</strong> and the command shortcut is <strong>insonic CLI</strong>. The desktop shortcut is <strong>insonic</strong>. Integrations follow the selected clients. If an existing shortcut with the exact optional name belongs to another installation or to you, the MSI refuses to overwrite it. Deselect that integration or move your existing shortcut, then retry.</li>
<li>Choose <strong>Install</strong> to commit the fresh installation. The execution page shows Windows Installer progress and the current phase. <strong>Cancel</strong> asks for confirmation while cancellation remains available; allow rollback to finish before closing the result. The final page distinguishes success, cancellation and failure.</li>
<li>After successful fresh installation, keep the checked <strong>Launch insonic</strong> option to open the desktop when selected. For CLI-only, <strong>Open insonic CLI</strong> opens a persistent command session with useful help/setup guidance. <strong>Open documentation</strong> is a separate, initially unchecked option. Choose either, both or neither, then select <strong>Finish</strong>. Documentation opens the installed version’s local HTML in the configured Windows HTML/browser association. If it cannot open, the correction explains how to open <code>help/index.html</code>, configure an HTML browser or use installer <strong>Repair</strong>; the committed installation remains available.</li>
<li>Neither completion action runs after unattended installation, upgrade, change, repair, removal, cancellation or failure. Those operations have their own result heading and one <strong>Finish</strong> or <strong>Close</strong> action.</li>
<li>Use <a href="/docs/v1.0.2/setup/">optional first-run setup</a>, open an existing library or choose <strong>Set up later</strong>. Local filesystem/SQLite/LadybugDB defaults need no service account or API key. Installing insonic does not download inference models or elect connected routes.</li>
</ol>
<h3 id="optional-checksum-comparison">Optional checksum comparison</h3>
<ol>
<li>
<p>Save <code>SHA256SUMS</code> beside the downloaded setup EXE.</p>
</li>
<li>
<p>Open PowerShell in that download folder and replace VERSION below:</p>
<pre tabindex="0" aria-label="Code example"><code class="language-powershell"><span class="hljs-built_in">Get-FileHash</span> <span class="hljs-literal">-Algorithm</span> SHA256 <span class="hljs-string">&quot;.\insonic_VERSION_windows_amd64_setup.exe&quot;</span>
</code></pre>
</li>
<li>
<p>Compare the complete hexadecimal hash with the line for that exact filename in <code>SHA256SUMS</code>. Matching letters can differ in case. If bytes do not match, discard that download and retrieve the official asset again; do not install it.</p>
</li>
</ol>
<h2 id="prerequisites">Prerequisites</h2>
<p>Both clients require the Microsoft Visual C++ v14 x64 runtime. Use <a href="https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170">Microsoft's runtime guidance</a> and <a href="https://aka.ms/vc14/vc_redist.x64.exe">official x64 installer</a>. Download the complete installer while online for transfer to an offline computer.</p>
<p>Desktop application additionally requires the WebView2 Runtime. Microsoft's <a href="https://developer.microsoft.com/en-us/microsoft-edge/webview2/">download page</a> and <a href="https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution">distribution guidance</a> distinguish the online Evergreen Bootstrapper from the x64 Evergreen Standalone Installer for offline installation. Microsoft Edge itself does not replace WebView2. CLI-only does not require it.</p>
<p>The MSI explains missing prerequisites. Install the relevant official runtime, honor its restart instructions, then retry the MSI. Prerequisite installers may request administrative approval depending on their chosen mode; the insonic per-user MSI does not request an all-users installation. Removing insonic does not remove shared Microsoft runtimes. Loader errors and unavailable dependencies are not a license or reputation confirmation.</p>
<h2 id="download-and-windows-warnings">Download and Windows warnings</h2>
<h3 id="edge-says-the-download-is-not-commonly-downloaded">Edge says the download is not commonly downloaded</h3>
<ol>
<li>Confirm the download's filename, version and official release address. An unknown/not-common reputation warning differs from a file reported as malicious.</li>
<li>For the unknown-file branch in Microsoft Edge, open the download item's <strong>...</strong> menu, then choose <strong>Keep</strong>, <strong>Show More</strong> and <strong>Keep anyway</strong> when offered. This retains the selected download.</li>
<li>If the warning reports malware, or device policy removes continuation, record the exact warning and use the <a href="#support-checklist">support checklist</a>. Do not apply unknown-file instructions to a reported-malicious detection.</li>
</ol>
<p>Microsoft documents these controls and managed-policy differences in <a href="https://learn.microsoft.com/en-us/deployedge/microsoft-edge-security-smartscreen">Edge SmartScreen guidance</a>. Other browsers have different controls; use their matching guidance.</p>
<h3 id="windows-protected-your-pc">Windows protected your PC</h3>
<ol>
<li>If this application-reputation dialog appears, select <strong>More info</strong>.</li>
<li>Check the displayed file matches your selected official download. This unsigned release does not have a verified publisher signature.</li>
<li>Select <strong>Run anyway</strong> if that control is available and you intend to run the selected file. If it is absent, use the support checklist; organization policy can prevent continuation.</li>
</ol>
<p>Microsoft's <a href="https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/publish-first-app">first-app guide</a> documents those controls, and <a href="https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation">SmartScreen reputation guidance</a> explains unsigned-file reputation and enterprise blocks. The dialog is conditional; every MSI or extracted application need not show it.</p>
<h3 id="permission-to-change-the-device">Permission to change the device</h3>
<p>A User Account Control prompt concerns elevation. It is separate from SmartScreen and Apache license acceptance. A prerequisite installer or an administrator-directed change can need permission even though insonic installs per user.</p>
<ol>
<li>Identify the program and requested change. An unsigned program has no verified publisher identity.</li>
<li>Choose <strong>Yes</strong> only for the identified change you intend to allow, or <strong>No</strong> to decline it.</li>
<li>A standard account may instead need administrator credentials. Ask your administrator rather than entering credentials into the insonic setup guide or an unrelated window.</li>
</ol>
<p><a href="https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works">Microsoft's UAC documentation</a> distinguishes administrator consent from standard-user credential prompts and explains secure-desktop behavior.</p>
<h3 id="smart-app-control-s-mode-or-organization-policy-blocks-execution">Smart App Control, S mode or organization policy blocks execution</h3>
<p>Smart App Control can reject an unsigned/untrusted file and currently offers no individual-app override. <strong>More info / Run anyway</strong> does not bypass it. Contact the developer or device administrator with the support checklist. Microsoft's <a href="https://support.microsoft.com/en-us/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions">current FAQ</a> also explains that recent Windows updates can permit re-enabling Smart App Control without a clean installation; older universal reset claims are not applicable to every device.</p>
<p>Windows S mode permits Microsoft Store applications. Leaving S mode is a one-way device choice, not a normal warning acknowledgment. Read <a href="https://support.microsoft.com/en-us/windows/experience/platform-variants/windows-10-and-windows-11-in-s-mode-faq">Microsoft's S mode FAQ</a> and consult the device owner or administrator before deciding.</p>
<p>App-source recommendations are another setting. On Windows 11 they appear under <strong>Settings &gt; Apps &gt; Advanced app settings &gt; Choose where to get apps</strong>, with options depending on the device. Microsoft's <a href="https://support.microsoft.com/en-us/windows/apps/change-your-app-recommendation-settings-in-windows">app recommendation guidance</a> explains those choices. Organization controls may be locked and can prohibit unsigned or outside-store installation. Global antivirus, Defender, SmartScreen and organization-policy disabling are not steps in the normal installation procedure.</p>
<h2 id="change-repair-upgrade-or-remove">Change, repair, upgrade or remove</h2>
<ol>
<li>Finish or explicitly cancel selected work in Jobs or CLI work commands, then close clients from the installation being changed. Closing the desktop does not cancel durable work. Allow the hidden runtime at least 31 seconds of inactivity to exit; new requests reset activity. <a href="/docs/v1.0.2/desktop/#close-the-old-installation-before-maintenance">Desktop maintenance guidance</a> explains how to identify remaining processes.</li>
<li>Open <strong>Settings &gt; Apps &gt; Installed apps</strong>, find <strong>insonic</strong>, and use its offered maintenance/removal action. The installer supports feature changes, repair and removal. If active work prevents replacement, close that work and retry; maintenance does not silently terminate it.</li>
<li>For an upgrade, download and open the newer matching setup EXE. Before removing the working version, setup validates a retained full MSI source and snapshots the previous program path, clients and shortcuts. Failed or cancelled replacement restores the prior installed registration and owned program bytes before setup returns, retaining the original failure or cancellation result. When moving an upgrade to a different program directory, active work under the registered old directory must also be closed before replacement. Older-version installation is rejected. Retain a <a href="/docs/v1.0.2/storage/">library backup</a> because program rollback does not reverse independently accepted library changes.</li>
<li>For removal, select <strong>Uninstall</strong> and complete the MSI removal. It removes only owned program files and integrations. Libraries, media, settings, models, credentials, shared Microsoft runtimes and unrelated portable ZIP installations remain.</li>
</ol>
<p>Per-user configuration uses <code>%APPDATA%\insonic</code>; local data/cache/runtime coordination uses <code>%LOCALAPPDATA%\insonic</code>. Library data follows the actual elected profiles. Native protected credentials remain in Windows Credential Manager; vault/credential configuration uses the library's private secret area. Preserve these locations during ordinary program removal. See <a href="/docs/v1.0.2/storage/">storage</a>, <a href="/docs/v1.0.2/secrets/">credentials</a> and <a href="/docs/v1.0.2/models/">models</a>.</p>
<h2 id="recovery-sources-and-raw-msi">Recovery sources and raw MSI</h2>
<p>Setup retains the complete current MSI privately under <code>%LOCALAPPDATA%\insonic-setup</code>. During upgrade it needs space for the old and new full MSI sources, in addition to installed program files. Legacy-source validation can also require a temporary private cabinet copy. Recovery uses the retained package even when the downloaded MSI or setup EXE is gone. Successful upgrade removes the obsolete old source; successful removal cleans its source. Libraries, media, settings, models and credentials remain outside this cache.</p>
<p>A legacy installation may have no retained source. Missing or corrupt required recovery data stops the coordinated upgrade before old removal. Obtain the exact previous release's MSI and its SHA256SUMS digest, then supply both explicitly:</p>
<pre tabindex="0" aria-label="Code example"><code class="language-powershell">&amp; <span class="hljs-string">&quot;.\insonic_NEW_VERSION_windows_amd64_setup.exe&quot;</span> <span class="hljs-literal">--previous-msi</span> <span class="hljs-string">&quot;C:\Downloads\insonic_OLD_VERSION_windows_amd64_installer.msi&quot;</span> <span class="hljs-literal">--previous-sha256</span> <span class="hljs-string">&quot;PREVIOUS_MSI_SHA256&quot;</span>
</code></pre>
<p>Replace both versions, the local path and the complete digest. Source identity, digest and embedded inventory must match the previous installed release. Supplying the valid original package also repairs corrupt application-owned source bytes before upgrade starts. Setup does not fetch recovery packages over the network or request administrator privileges. If Windows started it elevated, it hands execution to the same account's limited token and waits for the result; an unavailable limited token produces a correction to reopen normally.</p>
<p>The raw <code>insonic_VERSION_windows_amd64_installer.msi</code> remains available for direct Windows Installer use and advanced deployment tooling. It bypasses coordinated source retention and recovery. On the reproduced Windows Installer failure, old files return while old registration is only advertised, so raw-MSI file rollback cannot establish a usable registered installation. Use setup for the coordinated guarantee. Installed Apps still uses native MSI maintenance and removal.</p>
<p>If recovery cannot finish, setup retains its local source and <code>pending.json</code> record, reports incomplete recovery and returns failure. Correct the reported local-source or active-work problem, then retry the same setup with <code>--resume-recovery</code> (add <code>--quiet</code> for unattended recovery). Private <code>last-result.json</code>, <code>setup.log</code> and recovery logs distinguish the original native result from recovery. A preflight refusal has no native result because the MSI did not run. Omit private paths and account details when sharing diagnostics.</p>
<h2 id="unattended-setup">Unattended setup</h2>
<p>Read the Apache License 2.0 before electing unattended acceptance. From an existing PowerShell session, choose the exact release and client selection:</p>
<pre tabindex="0" aria-label="Code example"><code class="language-powershell"><span class="hljs-variable">$arguments</span> = <span class="hljs-string">&quot;--quiet --accept-license --clients cli --start-menu 0 --desktop-shortcut 0&quot;</span>
<span class="hljs-variable">$setup</span> = <span class="hljs-built_in">Start-Process</span> <span class="hljs-literal">-FilePath</span> <span class="hljs-string">&quot;.\insonic_VERSION_windows_amd64_setup.exe&quot;</span> <span class="hljs-literal">-ArgumentList</span> <span class="hljs-variable">$arguments</span> <span class="hljs-literal">-WindowStyle</span> <span class="hljs-keyword">Hidden</span> <span class="hljs-literal">-Wait</span> <span class="hljs-literal">-PassThru</span>
<span class="hljs-variable">$setup</span>.ExitCode
</code></pre>
<p>This <a href="https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process">PowerShell process invocation</a> waits for setup and reads its actual process exit code. Use <code>both</code>, <code>desktop</code> or <code>cli</code>; new installations default to both. <code>--install-dir PATH</code> selects a program location. Unattended upgrades retain prior choices unless explicitly overridden. Use setup for the installed version with <code>--quiet --repair</code> or <code>--quiet --remove</code> for maintenance. No completion launch or documentation action runs in quiet mode.</p>
<p>A result of 0 means the selected operation succeeded. Windows Installer can also return successful restart codes 3010 (restart required) or 1641 (restart initiated); setup preserves these <a href="https://learn.microsoft.com/en-us/windows/win32/msi/error-codes">native results</a> and suppresses automatic restart requests. Native 1602 means cancellation; 1603 means failure. Recovery preserves those original codes even when it restores the previous version successfully. Preflight failures return 1603 before starting MSI work. Recovery runs synchronously under the ordinary invoking account.</p>
<h2 id="portable-zip-alternative">Portable ZIP alternative</h2>
<ol>
<li>Choose the exact Windows Desktop + CLI or CLI-only ZIP and install its applicable prerequisites.</li>
<li>Extract the complete tree. Keep companions, native libraries, notices, corresponding sources and offline help together.</li>
<li>Follow <a href="/docs/v1.0.2/desktop/#install-a-windows-zip">Windows ZIP installation</a> to copy into a stable program directory and choose a separate library.</li>
<li>Open <code>insonic-desktop.exe</code> when included, or use <code>insonic.exe</code> from an already open terminal. ZIP copying creates no MSI registration, Installed Apps entry, shortcut, PATH integration or supplied uninstaller.</li>
</ol>
