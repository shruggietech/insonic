2:T14b0,<h1 id="delivery-outcomes">Delivery outcomes</h1>
<p>Delivery follows the dependencies between usable capabilities. GitHub Issues, milestones and the Project track implementation progress; this page explains how the product outcomes build on each other.</p>
<table>
<thead>
<tr>
<th>Outcome</th>
<th>Result</th>
<th>Depends on</th>
</tr>
</thead>
<tbody>
<tr>
<td>Platform and dependency contracts</td>
<td>Native CLI/runtime and desktop communication, pinned Cueson and graph libraries, hidden process launch, encrypted secrets and offline help on Windows, macOS and Linux</td>
<td>Shared application contracts</td>
</tr>
<tr>
<td>Runtime and configurable storage</td>
<td>Workspace ownership, durable jobs, migrations, model registry and complete filesystem/S3 and SQLite/PostgreSQL behavior</td>
<td>Platform contracts</td>
</tr>
<tr>
<td>Unified media library</td>
<td>Audio/video import, original identity, raw metadata capture, recording dates, per-item batch inputs and relocation</td>
<td>Runtime and storage</td>
</tr>
<tr>
<td>Correlated local subtitles</td>
<td>Supplied subtitle tracks, mapped audio derivatives, local recognition, source-timed speaker intervals and Cueson artifacts</td>
<td>Media library</td>
</tr>
<tr>
<td>Configurable processing</td>
<td>Readable presets, task capabilities, local/hosted routing and per-stage overrides</td>
<td>Subtitle and job contracts</td>
</tr>
<tr>
<td>Speaker continuity and terminology</td>
<td>Voices, names, aliases, reversible attribution, library-wide audio selection and transcription context</td>
<td>Processing and source-timed intervals</td>
</tr>
<tr>
<td>Desktop library and help</td>
<td>GUI packages that include the CLI, common core operations, playback, progress and release-matched offline docs</td>
<td>Runtime, media and speaker contracts</td>
</tr>
<tr>
<td>Evidence and querying</td>
<td>Chunked source assertions, ordered LadybugDB/ArcadeDB projection and source-linked word/speaker/time queries</td>
<td>Subtitle and speaker contracts</td>
</tr>
<tr>
<td>Visual exploration</td>
<td>Calendar/media timeline, saved force-directed graph views and keyboard/table alternatives</td>
<td>Desktop and graph queries</td>
</tr>
<tr>
<td>Optional query assistance</td>
<td>Configured model suggestions and elected validated read-only execution</td>
<td>Processing and query contracts</td>
</tr>
<tr>
<td>Durable distribution</td>
<td>Portable backups, expanded acquisition, signed packages and synchronized release/docs/schema publication</td>
<td>Installable packages and recovery contracts</td>
</tr>
<tr>
<td>Optional speaker models</td>
<td>Immutable corpus snapshots, elected training, versioned speaker-associated artifacts and CLI discovery/retrieval</td>
<td>Runtime, processing and speaker contracts</td>
</tr>

Core feature parity is the goal; matching release documentation identifies any advanced or experimental CLI capabilities awaiting GUI controls.</p>
<p>Optional speaker training can proceed once speaker, corpus and adapter contracts exist, alongside graph and desktop work. It does not require completion of every visual or distribution feature. A platform experiment can change a framework, dependency pin or packaging method while preserving the three required operating systems and supported backend behavior.</p>
<p>Direct library access and querying do not require an AI account or a model download. Training and query assistance are elective. Users' observations after releases become focused corrective work through the same issue-driven workflow.</p>
