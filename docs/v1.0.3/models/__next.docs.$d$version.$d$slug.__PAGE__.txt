32:T4eea,<h1 id="model-references-and-acquisition">Model references and acquisition</h1>
<p><a href="/docs/v1.0.3/processing-setup/">Local processing setup</a> exposes the complete pinned Whisper Tiny and Community-1 choices, verified local snapshot reuse and elected filesystem/S3 destinations. Model acquisition remains durable shared work with byte and file progress.</p>
<h2 id="exact-identities-and-short-references">Exact identities and short references</h2>
<p>Downloaded base models declare exact names, model versions, upstream revisions,
capabilities, license metadata and every required file's role, URL, SHA-256 and
size. Name and version identify one immutable installation. A conflicting
manifest for that pair is rejected; changed files require another version.
Registration does not imply its bytes are available.</p>
<p>Names, model versions and upstream revisions preserve their exact registered
Unicode text, including whitespace-only values and line breaks. Registration
does not trim or normalize these immutable identities. Human CLI output quotes
these fields and escapes control characters, so a space or line break remains
visible; JSON retains the original string. Use the installation UUID when an
identity is inconvenient to enter.</p>
<p>Model references accept an installation UUID, <code>base:UUID</code>, <code>speaker:VERSION_UUID</code>,
a workspace alias, or <code>source:NAME/SELECTOR</code>. Aliases use lowercase ASCII names
of 1-64 characters, beginning with a letter and containing letters, digits,
periods, underscores or hyphens. They cannot collide with UUID syntax. Alias
targets declare one operation and exact base, speaker-version or hosted target.
Names are unique within their workspace. Ambiguous or unknown references never
select the first returned version or guess a download URL.</p>
<p>Alias records have stable UUIDs and optimistic revisions. Retarget and remove
require the current expected revision. Removal preserves a tombstone so an old
edit cannot change a recreated alias; recreation uses the existing ID/revision.
Changing an alias affects future submissions, never accepted job elections.</p>
<p>Direct bundle acquisition reports an exact base target with an empty operation;
accepting the bundle does not establish inference compatibility for a task.
Pipeline inspection retains an unavailable reference as a <code>missing</code> selection
with an <code>unresolved</code> target and the intended operation. It reports no model ID,
manifest digest or upstream revision until resolution succeeds.
An alias declared for another operation retains its exact target and reports
the operation mismatch as incompatible. Direct <code>models resolve</code> and pipeline inspection succeed with <code>compatible: false</code> for this inspection, retaining target, alias revision, manifest digest and upstream revision. Execution election still rejects it before acquisition or inference.</p>

<h2 id="configured-discovery">Configured discovery</h2>
<p>Sources are explicit revisioned workspace records with a unique short name,
catalog URL, optional opaque credential UUID and an explicit loopback HTTP
exception. Discovery reads bounded metadata and reports declared entries,
complete manifests, compatibility and availability separately. A discovered
entry is not presented as a verified installed model. Custom manifests remain
supported; no mandatory curated-model list is imposed.</p>
<pre tabindex="0" aria-label="Code example"><code class="language-sh"><span class="hljs-title">insonic</span> models <span class="hljs-built_in">source</span> list <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models <span class="hljs-built_in">source</span> <span class="hljs-built_in">set</span> <span class="hljs-variable">SOURCE_ID</span> <span class="hljs-attr">--input</span> source-update.json <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models <span class="hljs-built_in">source</span> show <span class="hljs-variable">SOURCE_ID</span> <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models discover <span class="hljs-variable">SOURCE_ID</span> <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models resolve <span class="hljs-built_in">source</span>:custom/speech:v1 <span class="hljs-attr">--operation</span> transcription <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models <span class="hljs-built_in">source</span> remove <span class="hljs-variable">SOURCE_ID</span> <span class="hljs-attr">--expected-revision</span> <span class="hljs-variable">REVISION</span> <span class="hljs-attr">--json</span>
</code></pre>
<p>A source update has <code>expected_revision</code> and a <code>source</code> object containing <code>id</code>,
<code>name</code>, <code>state</code>, <code>url</code>, optional <code>credential_id</code> and <code>local_http</code>. New records use
expected revision zero; updates/removal use the returned revision. Source URLs
and file URLs must follow the configured transport policy: HTTPS by default,
explicit loopback HTTP where permitted, no password/user information or query
credentials, and bounded declared-origin redirects. Saved credential values are not
included in source records, manifests, durable work or status.
Catalog content cannot authorize loopback file downloads. Such files require
an owner-configured loopback source with its local opt-in enabled. An explicit
owner-supplied manifest retains its own local transport option.</p>
<p>The implemented source protocol is a <code>model-catalog</code> document with
<code>schema_version</code>, and up to 128 <code>entries</code>, each containing <code>selector</code> and a
complete <code>manifest</code>. Responses are bounded to 4 MiB. Selectors may represent
tags or branches, but resolution freezes the returned exact bundle and its
declared upstream revision. Catalog providers should supply immutable upstream
revisions wherever available; unknown declarations remain explicit. Every file,
including tokenizer/configuration auxiliaries, still requires SHA-256 and size.
Updating the catalog later cannot change an existing election.</p>
<p>Direct Hugging Face APIs/CDN downloads are not an implemented source adapter.
An explicitly configured catalog can describe supported URLs; unsupported
provider redirects or formats are diagnosed instead of silently changing the
transport policy. <a href="https://huggingface.co/docs/huggingface_hub/main/guides/download">Revision-pinned acquisition guidance</a>
explains why mutable branches are convenience selectors rather than job identity.</p>
<h2 id="compatibility-before-execution">Compatibility before execution</h2>
<p>Optional manifest <code>compatibility</code> declares <code>adapter</code>, <code>contract_version</code>,
<code>architecture</code>, <code>runtime_format</code>, and optional <code>sample_rates</code> and <code>channels</code>.
Inspection validates task, required file roles, adapter contract and audio
requirements without loading a model. Available and compatible are different
properties: custom bundles may be registered/acquired while lacking a supported
execution adapter.</p>
<p>Installed inventory includes declared capabilities and compatibility with the
default adapter for each operation. Shared selectors use these summaries to
label incompatible bundles while retaining exact identity and availability.
Reference inspection checks the requested operation; a saved pipeline's
inspection also checks its explicitly selected stage adapter.</p>
<p>The current local adapters require contract version <code>1</code>. <code>faster-whisper</code>
consumes Whisper/CTranslate2 files named <code>config.json</code>, <code>model.bin</code>,
<code>tokenizer.json</code> and <code>vocabulary.txt</code>. <code>pyannote</code> consumes Pyannote/Torch files
named <code>config.yaml</code>, <code>embedding/pytorch_model.bin</code>,
<code>segmentation/pytorch_model.bin</code>, <code>plda/plda.npz</code> and
<code>plda/xvec_transform.npz</code>. Matching is case-sensitive and role paths are confined.
Their mapped engine input is 16000 Hz mono. Older accepted manifests without
explicit compatibility retain their original digests and are checked against
these established role contracts; they are not silently rewritten.</p>
<p>Unsupported task/runtime/architecture/version, missing roles and incompatible
audio requirements are diagnosed before inference. Downloading arbitrary
weights does not make them executable. A failed local selection does not choose
another model, device or hosted provider.</p>
<h2 id="acquisition-and-dependent-work">Acquisition and dependent work</h2>
<pre tabindex="0" aria-label="Code example"><code class="language-sh"><span class="hljs-title">insonic</span> models register model.json <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models acquire model.json <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> work show <span class="hljs-variable">WORK_ID</span> <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> work <span class="hljs-built_in">wait</span> <span class="hljs-variable">WORK_ID</span> <span class="hljs-attr">--timeout-ms</span> 30000 <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models list <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models show <span class="hljs-variable">MODEL_ID</span> <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models verify <span class="hljs-variable">MODEL_ID</span> <span class="hljs-attr">--json</span>
<span class="hljs-title">insonic</span> models materialize <span class="hljs-variable">MODEL_ID</span> <span class="hljs-attr">--json</span>
</code></pre>
<p>Processing/import elections resolve references once, validate compatibility and
freeze exact IDs, complete manifest digests, upstream/adapter identities and
effective settings. Missing selected bundles acquire automatically before
dependent processing. Saved pipeline inspection remains free of acquisition
and inference. Direct processing fields and import's <code>--diarization-model-id</code>
use the same reference grammar; see <a href="/docs/v1.0.3/pipelines/">pipelines</a> and
<a href="/docs/v1.0.3/ingestion/">import</a>.</p>
<p>Acquisition returns durable work immediately. Underlying acquisition is shared
by exact workspace/bundle identity; explicit requests and processing consumers
retain independently cancellable parent work. Waiting consumers leave worker
slots free for acquisition. Work inspection identifies frozen selections,
acquisition IDs and phase. A failed/cancelled dependency produces a diagnosed
acquisition failure, not a completed pipeline. Retrying the parent repairs its
original dependency without following a later alias or source change.</p>
<p>Downloads resume bounded partial transfers, verify all hashes/sizes and publish
files before accepting availability. Already available bytes are verified,
not trusted by cache filename. Missing/corrupt bytes require exact recovery.
Cancelled/stale work cannot publish a late processing result. Cancelling one
consumer does not cancel shared acquisition still used by another consumer.</p>
<p>Model show includes response-only <code>registry_state</code>, <code>readiness</code> and <code>verification</code> facts. Existing shared acquisition work adds its exact ID and state; inspection does not invent a work item or change stored availability. Registered resources report not acquired; active acquisition reports acquiring. Availability alone is not a verification performed by the current inspection. Verify/materialize retain these facts even when they fail, distinguishing proven damaged bytes from an unavailable storage backend. Reacquire with the original manifest file, or inspect/retry existing acquisition work; the acquisition operand is not a model UUID.</p>
<p>Model materialization returns an object with verified readiness and a <code>files</code> array. Each entry names its immutable manifest role, model ID/digest, declared size/SHA-256, exact publication ID, local path and lease ID/details. Materialization returns verified local paths with renewable artifact leases.
Release leases after the consumer finishes. Temporary/base caches are separate
from durable speaker profiles and trained artifacts; their cleanup cannot purge
trained output or active readers.</p>
<h2 id="portability-and-speaker-versions">Portability and speaker versions</h2>
<p>Artifacts use configured filesystem or generic S3 storage. Exact manifests,
aliases, sources and model relationships use portable SQLite/PostgreSQL catalog
records with schema migration and snapshot proof validation. Exports contain
opaque credential references, not secret values or transient materialization
paths. Graph relationships remain projections of catalog authority.</p>
<p><code>speaker:VERSION_UUID</code> inspection preserves the existing family, producing
speaker, training run, dataset and artifact lineage. Hosted-only targets retain
their explicitly configured provider/remote handle and report that local
downloadable weights are unavailable. Neither an alias nor a retained artifact
fabricates a valid trained output or a runnable unsupported adapter.
Local processing/import model selections require compatible base bundles.
Hosted aliases support identity inspection; executing a hosted route uses the
existing saved pipeline's explicit endpoint, remote model and adapter settings.
Trained speaker references expose immutable output lineage. Compatible embedding
profiles can be elected for roster-constrained identity matching; arbitrary
trained weights require their declared consumer and are not substituted for a
recognition or diarization base model. <a href="/docs/v1.0.3/voice-models/">Speaker-associated training</a>
supports exact version discovery/fetch and revisioned current profile selection.
The Models screen exposes these operations, while Speakers starts dataset creation
and elected training and Library starts matching-only work.</p>
<p>CLI/runtime and desktop share these operations. Models settings support
reference configuration/discovery; shared selectors and Jobs distinguish exact
identity, availability, compatibility and acquisition. See <a href="/docs/v1.0.3/desktop/">desktop</a>,
the rendered <a href="/docs/v1.0.3/contracts/">JSON contracts</a> and <a href="/docs/v1.0.3/secrets/">credentials</a>.</p>
